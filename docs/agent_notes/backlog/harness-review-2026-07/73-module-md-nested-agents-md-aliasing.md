# 73. The MODULE.md convention predates nested AGENTS.md and is invisible to agents that only discover per-directory AGENTS.md files

Status: Done — option (c) documented 2026-07-02; stub generation and rename deferred.
Lens: reference-fitness · Area: docs-conventions · Severity: med · Size: M · Confidence: med
Theme: agents-md-interop · Source: Musi AI-harness review 2026-07-01 (multi-agent + Codex second opinion + web research)

## Problem
Musi's per-directory orientation docs are `MODULE.md` / `*-MODULE.md` files (47 of them), indexed into `MODULE-INDEX.md` and governed by a written charter. The convention works, but the ecosystem has since standardized on *nested `AGENTS.md`* for exactly this job: per the review's web research, AGENTS.md is now a Linux Foundation-hosted standard adopted across 60k+ repos, OpenAI's own monorepo carries ~88 nested AGENTS.md files, and Codex, Cursor, and Gemini CLI discover nested AGENTS.md natively when working in a subtree (Claude Code reads CLAUDE.md and AGENTS.md). In this repo, MODULE.md reaches an agent only if it obeys one prose instruction in the root AGENTS.md — no harness config, hook, or agent-native discovery mechanism surfaces it. A visiting agent (or a human adopter copying the pattern) that relies on native nested-AGENTS.md discovery sees nothing. For a public reference, the repo should either speak the standard dialect or explicitly document why it doesn't and how the mapping works.

## Decision

Implemented option (c) only on 2026-07-02: document the mapping in
`docs/module-docs.md` and `docs/ai-harness.md`. Re-verification found 47
tracked `*MODULE.md` files and zero `MODULE.md` references in `.claude/` or
`.codex/` configs, so no active agent used in this repo depends on native
nested-`AGENTS.md` discovery today.

Options (a) generated nested `AGENTS.md` stubs and (b) wholesale convention
rename are deferred. The 47-file stub/rename churn is not justified until a
repo-used agent or concrete adopter needs native nested-`AGENTS.md` discovery.

## Evidence
- 47 `*MODULE.md` files tracked (verified `git ls-files | grep -cE '(^|/)[A-Za-z-]*MODULE\.md$'` → 47); index generated by `/workspace/scripts/generate-module-index.sh` (`bun run module:index`, `--check`/`--json` gate modes at lines 72-104); contract at `/workspace/docs/module-docs.md`.
- `/workspace/AGENTS.md` Working Model — "Read the nearest `MODULE.md` or `*-MODULE.md` before editing feature, service, hook, or socket areas that have one." This single instruction is the only agent-facing surfacing.
- Verified NO references to MODULE.md anywhere in `.claude/` or `.codex/` (grep of both trees is empty) — the review's assumption that protected-files advisories also surface MODULE.md does **not** hold; Codex gets the convention only because it natively reads the root AGENTS.md prose.
- Supporting surfaces that would need to follow any rename/aliasing: `/workspace/docs/ai-harness.md:61-63` (guides rows), `/workspace/harness.controls.json` (`doc-generator/module-index` control), `scripts/drift-ai/module-doc-paths*.ts` (stale-path sensor), `scripts/tests/test-generate-module-index.sh`, `docs/guides/add-module-doc.md`.

## Proposed direction
Design gate first — decide among:
(a) **Generate nested `AGENTS.md` stubs** from each MODULE.md (a 2-3 line pointer or `@MODULE.md`-style include), produced by the same generator family as `MODULE-INDEX.md` so they can't drift. Pro: native discovery for Codex/Cursor/Gemini; con: 47 stub files of tree noise plus generator/check plumbing.
(b) **Rename the convention wholesale** to nested AGENTS.md. Pro: standard-dialect; con: large churn across the sensor/index/guide surfaces above, loses the flat `<name>-MODULE.md` companion form (`docs/module-docs.md:33-35`), and root-vs-nested AGENTS.md semantics differ (instructions vs orientation contract).
(c) **Leave as-is and document the mapping**: a short "MODULE.md is our nested-AGENTS.md equivalent; adopters using native discovery should emit stubs" section in `docs/module-docs.md` + `docs/ai-harness.md`. Cheapest honest option and a fine first commit regardless of (a)/(b).

## Scope / caveats
Design-gated: measure real benefit before building (does any agent actually used here rely on native nested-AGENTS.md discovery? Codex in this repo is driven via the root AGENTS.md and skills today). If (a) is chosen, split into: generator + check, then stub emission, then doc updates. The external-adoption figures (Linux Foundation, 60k+ repos, 88 files in OpenAI's monorepo) come from the review's web research and were not locally verifiable — re-confirm before citing them in public docs. Whatever lands, keep `module:index:check` green and update the drift-ai module-doc-paths sensor scope.

# 43. Five vtt-drawer mutation-hook tests hand-roll the same tRPC failure-injection mock factory (FakeTRPCError + vi.hoisted gate)

Status: Done — implemented 2026-06-14 (batch 5a)
Lens: maintainability · Area: client · Severity: low · Size: S-M · Confidence: high
Theme: mock-scaffold-duplication · Source: Musi test-suite audit 2026-06-13 (multi-agent, adversarially verified)

## Problem
Every mutation-hook test under `packages/client/src/hooks/vtt-drawer/` re-implements the same `vi.mock("@/lib/trpc.js")` factory by hand. The recipe is identical in all five files: import `createMockTRPCModule()`, spread the module, then reach into one mutation node, spread it, and override its `mutationOptions` so that — when a `vi.hoisted` `mutationFailure` gate is armed — the returned `mutationFn` rejects with `new FakeTRPCError(code, message)`. The only things that vary between files are the mutation path being patched (`castSpell.dropConcentration`, `castSpell.cast`, `character.useFeature`, `encounter.updateParticipant`, `encounterCombat.attemptAttack`) and the toast string asserted later. `use-drop-concentration.test.ts` and `use-feature-use.test.ts` are byte-for-byte the same factory apart from the path name and the hook under test.

This is the maintainability cost left standing *after* drift-ai #26 (Done): that finding pulled the `FakeTRPCError` class itself into `packages/client/src/test/mock-trpc-helpers.ts`, but it stopped at the class. The surrounding ~35-line spread/override plumbing — the part that actually wires the error shape into the mutation graph and gates it on the hoisted flag — was never extracted, so `mock-trpc-helpers.ts` exports `FakeTRPCError` and `makeMutation` but no failure-injection wrapper. Each of the five tests therefore still re-derives the same nested-spread boilerplate. When the error contract the hooks branch on changes (today `onTRPCError` reads `error.data.code`; tomorrow it might also read `data.httpStatus`), the injection plumbing has to be updated in five places in lockstep, and any copy that lags silently stops exercising the real branch.

## Evidence
- `packages/client/src/hooks/vtt-drawer/use-drop-concentration.test.ts:9-43` — `mutationFailure` `vi.hoisted` gate (lines 9-11) plus the spread/override of `castSpell.dropConcentration.mutationOptions` whose `mutationFn` rejects with `new FakeTRPCError(code, message)` (lines 27-37). Imports `FakeTRPCError` from `@/test/mock-trpc-helpers.js` at line 4.
- `packages/client/src/hooks/vtt-drawer/use-confirm-cast.test.ts:9-57` — same plumbing for `castSpell.cast`, plus a *second* `vi.hoisted` `mutationGate` (lines 13-16) and an extra branch (lines 41-49) that returns a never-resolving `mutationFn` to exercise in-flight `isPending`.
- `packages/client/src/hooks/vtt-drawer/use-feature-use.test.ts:9-43` — the identical factory, only the path changed to `character.useFeature`; structurally a near-clone of `use-drop-concentration.test.ts`.
- `packages/client/src/hooks/vtt-drawer/use-monster-hp-update.test.ts:10-44` — same factory for `encounter.updateParticipant` (gate at lines 10-12, override at 26-39).
- `packages/client/src/hooks/vtt-drawer/use-weapon-attack.test.ts:13-50` — the same failure gate (lines 13-15) interleaved with a *separate* `map.get.queryOptions` override (lines 17-19 hoisted `mapQueryOverride`, applied at 36-49); the `encounterCombat.attemptAttack` failure branch itself runs at lines 57-66. `packages/client/src/test/mock-trpc-helpers.ts:8` defines `FakeTRPCError` but its exports (verified: `makeListQuery`, `makeGetQuery`, `makeMutation`, `makeQueryFilter`, `makeInfiniteQuery`) include no failure-injection/gate wrapper.

All five `vtt-drawer/` mutation-hook tests use this factory. Post the `692b437a` merge, the identical gate-in-`mutationOptions` + `Promise.reject(new FakeTRPCError(code, message))` factory also appears in three more client hook tests that lacked it at audit HEAD: `packages/client/src/hooks/use-ability-roll.test.ts` (gate at line 9, override 27-33), `packages/client/src/hooks/use-weapon-roll.test.ts` (gate at line 19, override 61-66), and `packages/client/src/hooks/character-sheet/use-character-spells.test.ts` (gate at line 10, override 28-34). The pattern now spans **9 client test files** (was 5), and `FakeTRPCError` importers grew from 6 to **14** client files. This expands, not invalidates, the finding — re-grep `rg -l "Promise.reject\(new FakeTRPCError\(code, message\)\)" packages/client/src` before implementing to capture the current footprint.

## Proposed direction
Add one helper to `packages/client/src/test/mock-trpc-helpers.ts` — e.g. `buildTRPCMockWithFailableMutation(path, gate)` — that takes a dotted mutation path (`"castSpell.dropConcentration"`) and a hoisted gate object, and returns the spread/override module shape, deep-spreading down to the named node and overriding only its `mutationOptions` to inject the `FakeTRPCError` rejection when the gate is armed. Pair it with a small arm controller (`armFailure(code, message)` / `clearFailure()`) so the `beforeEach` reset stays one line. The pure cases — `use-drop-concentration`, `use-feature-use`, `use-monster-hp-update`, plus the three structurally-identical hooks/ tests the merge added (`use-ability-roll`, `use-weapon-roll`, `character-sheet/use-character-spells`) — then replace their ~35-line factory with a single call naming the path. `use-confirm-cast` composes the helper with its extra `mutationGate` in-flight branch, and `use-weapon-attack` composes it with its `map.get` `queryOptions` override; both compose rather than re-deriving the failure plumbing.

Coverage is fully preserved: the failure / CONFLICT / `isPending` / toast assertions are unchanged — only the rejection-injection scaffolding is deduplicated. There is no run-time speed dimension here (these are fast jsdom hook tests); the win is maintainability and a single source of truth for the `error.data.code` contract.

Estimated impact: removes roughly 30-35 lines of near-identical mock plumbing from each of the ~9 client test files that now carry the factory (the original five vtt-drawer files plus the three hooks/ tests the merge added) and centralizes the error-shape contract so a future `onTRPCError` change (e.g. reading `data.httpStatus`) updates one helper instead of nine copies.

## Scope / caveats
Touch the five `packages/client/src/hooks/vtt-drawer/` mutation-hook test files plus the three additional hooks/ tests the merge added (`use-ability-roll.test.ts`, `use-weapon-roll.test.ts`, `character-sheet/use-character-spells.test.ts`) and `packages/client/src/test/mock-trpc-helpers.ts`; no source or assertion changes. Explicitly out of scope: only `packages/client/src/hooks/character-sheet/use-rest.test.ts` and `use-weapon-masteries.test.ts` — these two use a structurally different approach (a plain `vi.fn` `mutationFn` driven by `mockResolvedValue` / `mockRejectedValueOnce` / `createDeferred`, never touching `FakeTRPCError`) — so this helper does not and should not absorb them; folding them in would be a different refactor. Note `character-sheet/use-character-spells.test.ts` is **not** in this exclusion: it uses the in-scope `FakeTRPCError` gate factory (lines 10, 28-34) and is an additional helper candidate.

The helper must compose cleanly with the two non-pure cases: `use-confirm-cast`'s second hoisted gate for in-flight `isPending`, and `use-weapon-attack`'s `map.get` `queryOptions` override that is interleaved with the failure branch in the same `useTRPC` factory. Design the helper to return a node-shaped fragment that callers can spread alongside their extra overrides, not a whole sealed module, so these two compose without forking the helper.

Sibling worth noting (optional, can stay out of the initial refactor): the same `Promise.reject(new FakeTRPCError(code, message))` pattern is also applied to **queries**, not just mutations — `collection-card.test.tsx` (homebrew) injects it into a `queryFn`/`queryOptions` at line 37. A truly central helper could cover both the `mutationOptions` and `queryOptions` failure-injection shapes (the existing `makeListQuery`/`makeGetQuery` helpers already model the query side), broadening the single-source-of-truth win.

This finding legitimately compounds (does not duplicate) drift-ai #26 (`26-client-fake-trpc-error-test-class-dup.md`, Done), which extracted only the `FakeTRPCError` class into the same module; #43 extends that module with the injection plumbing #26 left behind. It is the client-side sibling of drift-ai #24 (`24-server-test-trpc-mutation-inject-helper-dup.md`, a server-side mutation-inject helper dup) — same idea, different package. Low blast radius confined to one directory; no coverage gap, no sequencing dependency beyond #26 already being landed.

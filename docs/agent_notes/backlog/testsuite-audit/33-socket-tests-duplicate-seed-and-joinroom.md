# 33. Six socket integration tests duplicate the user/campaign/member beforeEach seed and a joinRoom helper instead of a shared socket fixture

Status: Proposed — read-only finding from the test-suite audit; NOT implemented. Re-verify file:line before acting.
Lens: maintainability · Area: server · Severity: med · Size: M · Confidence: high
Theme: server-test-fixture-duplication · Source: Musi test-suite audit 2026-06-13 (multi-agent, adversarially verified)

## Problem
Every socket integration test in `packages/server/src/socket/` rebuilds the same fixture by hand. Six files — `campaign-broadcast`, `campaign-room`, `character-broadcast`, `chat-broadcast`, `connection-handler`, and `encounter-broadcast` — each declare their own `DM_USER`/`PLAYER_*` `SessionUser` literals and run a byte-for-byte identical `beforeEach`: `cleanDb()`, `createSocketTestApp()`, a loop that raw-creates the users with the hardcoded `passwordHash: "not-a-real-hash"`, then a `prisma.campaign.create` with inline `members.createMany` rows. Four of those six (`campaign`, `character`, `chat`, `encounter-broadcast`) additionally redefine the exact same `joinRoom()` helper — `createAccessToken` → `ctx.createSocket` → `connectSocket` → `socket.emit("campaign:join", …)` and await the ack — character-for-character the same in each.

This is the standard duplication-drift hazard, on a surface that genuinely changes. The room-join handshake (`campaign:join` event name, ack shape, connect ordering) and the campaign-seed shape (member roles, the throwaway password hash) are exactly the kind of thing that gets revised; when it does, a dev must make the identical edit in four-to-six files in lockstep, and any file they miss either silently rots or fails in a way that looks unrelated to the change. A new dev writing the seventh socket-broadcast test will copy this boilerplate again because there is nothing else to copy. A shared `setupCampaignTestContext()` already exists and `fixtures.ts` already exports a `createTestUser()` that generates the password hash properly, yet none of the socket tests use either, and there is no shared socket `joinCampaignRoom` helper at all.

## Evidence
- `packages/server/src/socket/campaign-broadcast.test.ts:31-62` — `beforeEach` raw-creates users (`passwordHash: "not-a-real-hash"` at :41) plus campaign + members; `joinRoom` defined at :68-76 (`createAccessToken` → `ctx.createSocket` → `connectSocket` → emit `campaign:join` → await ack).
- `packages/server/src/socket/chat-broadcast.test.ts:52-84` — same `beforeEach` seed loop (`not-a-real-hash` at :62); byte-identical `joinRoom` at :90-98.
- `packages/server/src/socket/character-broadcast.test.ts:31` (seed, `not-a-real-hash` at :41) and `:68` (`joinRoom`) — same pair.
- `packages/server/src/socket/encounter-broadcast.test.ts:32` (seed, `not-a-real-hash` at :42) and `:69` (`joinRoom`) — same pair.
- `packages/server/src/socket/campaign-room.test.ts:18,24,33` — same hand-rolled `DM_USER`/`PLAYER_USER` literals and the same user/campaign `beforeEach` seed (`not-a-real-hash` at :42, :51), but inlines its single joins instead of defining a `joinRoom` helper.
- `packages/server/src/socket/connection-handler.test.ts:24,74-98` — sixth file carrying the raw user/campaign seed — here inside the disconnect `it` block at :74-98 (`not-a-real-hash` at :80), with a minimal cleanDb-only `beforeEach` at :24 (just `cleanDb()` + `createSocketTestApp()`); also inlines `campaign:join` (at :110, :113) rather than a helper.
- `packages/server/src/test/campaign-test-context.ts:65` — `setupCampaignTestContext()` already builds dm+players (with `userId`/`token`) and member rows; `packages/server/src/test/fixtures.ts:23` exports `createTestUser` (generates a real bcrypt hash) — neither is used by any socket test.
- `packages/server/src/test/socket-helper.ts:23,84` — `createSocketTestApp` and `connectSocket` already live here; no `joinCampaignRoom` or `seedSocketCampaign` exists anywhere (`rg joinCampaignRoom|seedSocketCampaign` → none).
- Verified counts: exactly 6 socket test files carry the raw user/campaign `beforeEach` seed; exactly 4 (`campaign`/`character`/`chat`/`encounter-broadcast`) define the byte-identical `joinRoom()`. `map-broadcast.test.ts` is a `vi.fn()`-based unit test with a fake `io` (no DB seed, no socket) and is correctly outside the set.

## Proposed direction
Add a small socket-specific fixture, the natural home being `packages/server/src/test/socket-helper.ts` (alongside `createSocketTestApp`/`connectSocket`), or a sibling `socket-test-context.ts`:

- `seedSocketCampaign(opts?)` — creates a DM plus N players and a campaign with member rows, reusing `createTestUser` for the user rows (which fixes the throwaway-hash duplication for free), generating ids rather than hardcoding them, and returning the `SessionUser`s plus `campaignId`.
- `joinCampaignRoom(ctx, user, campaignId)` — wraps `createAccessToken` → `ctx.createSocket` → `connectSocket` → emit `campaign:join` → await ack, returning the connected `TestClientSocket`.

Then migrate the six files to call them. Keep every file's distinct broadcast/edge-case assertions verbatim — the only thing removed is setup boilerplate, so coverage is identical. For the two files that inline joins (`campaign-room`, `connection-handler`), swap the inline `emit("campaign:join", …)` blocks for `joinCampaignRoom` only where the call is a plain happy-path join; leave any join that is itself the assertion target (e.g. tests that inspect the ack or the join/leave broadcast) inline so the behavior under test stays explicit.

Estimated impact: removes ~6 copies of the `beforeEach` seed and ~4 copies of `joinRoom`; the join/room handshake and campaign-seed shape then have one definition to edit instead of four-to-six in lockstep; faster onboarding for socket work (one fixture to learn). No measurable run-time change — these are the same DB writes and socket connects, just centralized.

## Scope / caveats
Do NOT try to reuse `setupCampaignTestContext` directly: it requires the HTTP `FastifyInstance` and builds the campaign via `injectTrpcMutation` (tRPC), whereas socket tests use `createSocketTestApp`; a separate socket helper is the correct shape, not a forced merge. The hardcoded user ids in the existing tests are not load-bearing for any assertion — they only need to match the JWT subject and the `campaignMember` rows — so a `seedSocketCampaign()` that generates ids and returns the `SessionUser`s satisfies the contract; verify this per file before deleting the literals (a few tests reference `DM_USER.id`/`PLAYER_A.id` directly in payload assertions, so the returned objects must expose those ids).

Test-only maintainability change; no correctness or coverage risk. Migrate file-by-file, running each file after its migration (`bun run test -- packages/server/src/socket/<file>.test.ts`) so a mistake is isolated. It is distinct from drift-ai #24 (the tRPC mutation inject-helper) — that targets `injectTrpcMutation` callers, not socket fixtures — and `map-broadcast.test.ts` is intentionally out of scope.

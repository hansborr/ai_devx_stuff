# 15. splitIntoBlocks (core spell block-splitter) is untested, and its test file is misnamed after a different module

Status: Proposed — read-only finding from the test-suite audit; NOT implemented. Re-verify file:line before acting.
Lens: defect-catching · Area: server · Severity: med · Size: S-M · Confidence: high
Theme: seed-pipeline-coverage · Source: Musi test-suite audit 2026-06-13 (multi-agent, adversarially verified)

## Problem
`packages/server/src/seed/spell-splitter.ts` exports three functions: `isPreambleHeader`, `isSectionHeader`, and `splitIntoBlocks`. The two predicates are trivial line classifiers. `splitIntoBlocks` (~35 lines) is the real work: it locates the `## Spell Descriptions` marker, slices everything after it, flushes a block on every `#2`–`#4` header, drops section headers (`### X Spells`) and preamble headers (`### Range`, etc.), filters out any leading block that does not start with a spell header, and throws `Could not find '## Spell Descriptions' marker` when the marker is absent. It is the block-segmentation core of the SRD spell seed-generation pipeline — every parsed spell flows from the boundaries it draws.

Yet `splitIntoBlocks` has zero test coverage. The only file in the directory that *looks* like it should cover this pipeline, `generate-srd-spells.test.ts`, does not test `generate-srd-spells.ts` at all: it imports and exercises only the two trivial predicates from `spell-splitter.js`. So the cheap predicates are thoroughly covered (a parameterized corpus of section headers, bold/italic preamble cases, adversarial long-input cases) while the actual segmentation logic and its missing-marker throw are completely unverified. The filename actively misleads: a developer changing `generate-srd-spells.ts` or `splitIntoBlocks` would open `generate-srd-spells.test.ts`, see green predicate tests, and wrongly conclude the block-splitter is protected.

This is one of two files in `packages/server/src/seed` that break the directory's `<module>.test.ts` <-> `./<module>.js` colocation convention (the other being `seed-srd.test.ts`, which is named after `seed-srd` but tests `seed-data-loader.js`). Six of the eight sibling test files import from the module they are named after; this one is named `generate-srd-spells.test.ts` but imports from `./spell-splitter.js`. Because `generate-srd-spells` is a one-time dev-run generator that regenerates committed seed JSON, a silent regression in block splitting (a swallowed spell, a leaked preamble block) would only surface as corrupted seed data on the next manual regen — exactly the kind of slow, hard-to-attribute breakage a colocated unit test is meant to catch at the source.

## Evidence
- `packages/server/src/seed/spell-splitter.ts:48` — `export function splitIntoBlocks(content: string): string[][]`; the missing-marker `throw new Error("Could not find '## Spell Descriptions' marker")` is at line 54, the header-flush loop at lines 61–77, and the leading-non-spell-block filter at line 81. No test references this function.
- `packages/server/src/seed/generate-srd-spells.test.ts:3` — `import { isPreambleHeader, isSectionHeader } from "./spell-splitter.js"`; the file's name says `generate-srd-spells`, but it only imports and tests the two `spell-splitter` predicates (two `describe` blocks, no `splitIntoBlocks` and no `generate-srd-spells` import).
- `packages/server/src/seed/generate-srd-spells.ts:28` — `const blocks = splitIntoBlocks(content)` is the sole production caller of the exported splitter; `rg "splitIntoBlocks" --type ts` shows no `*.test.ts` reference. (A same-named but file-local `splitIntoBlocks` exists in `generate-srd-rules-glossary.ts:30` with a different `{ header, body }[]` signature — a different function, not this export.)
- `packages/server/src/seed/` — eight `*.test.ts` files; six (`level-heading`, `seed-srd-equipment`, `spell-area-of-effect-overrides` (the test file `seed/spell-area-of-effect-overrides.test.ts`, importing from `./data/spell-area-of-effect-overrides.js`), `rules-glossary-parser/parse-glossary-entry`, `spell-parser/extract-spell-metadata`, `spell-parser/parse-spell-block`) import from their same-named `./<module>.js`, and two violate the convention: `generate-srd-spells.test.ts` (imports `./spell-splitter.js`) and `seed-srd.test.ts` (imports `readSeedJson` from `./seed-data-loader.js`, added by the merge).

## Proposed direction
Rename `generate-srd-spells.test.ts` to `spell-splitter.test.ts` (it already tests that module and nothing else), keeping the existing `isPreambleHeader`/`isSectionHeader` cases verbatim, and add `splitIntoBlocks` coverage against a small multi-spell markdown fixture that mirrors the real SRD shape (a `## Spell Descriptions` marker followed by `### X Spells` section headers, `### Range`/`### Components` preamble headers, and a handful of `####`-or-`###` spell headers with bodies). Assert: (1) block boundaries land on spell headers and bodies stay attached to their header; (2) section and preamble headers are dropped, not emitted as blocks; (3) any block before the first spell header is filtered out; (4) a fixture missing the `## Spell Descriptions` marker throws the exact error message. The module is pure (`string -> string[][]`) — no filesystem, no I/O, no flakiness, so the new cases are fast and deterministic.

Estimated impact: closes the coverage gap on the seed-generation core (a regression that swallows a spell or leaks preamble would currently ship silently into the committed seed JSON on the next manual regen) and removes a misleading filename, restoring the colocation convention for one of the directory's two violators (the merge-added `seed-srd.test.ts` -> `seed-data-loader.js` is the other and remains out of scope here). This is additive coverage plus a rename, so the change is near-zero runtime cost in CI (a few microsecond-scale pure-string assertions). Blast radius of the underlying bug class is bounded to corrupting generated seed data during a manual regen of a one-time dev generator, which is why this sits at the low end of `med` rather than higher.

## Scope / caveats
Pure rename plus additive tests; no source change to `spell-splitter.ts`, `generate-srd-spells.ts`, or any seed module. Preserve the existing `isPreambleHeader`/`isSectionHeader` cases exactly when moving them into the renamed file. The fixture must mirror the real SRD markdown shape so the boundary assertions are meaningful rather than tautological; copy a few representative header lines from the live splitter's regexes (`/^## Spell Descriptions/`, `/^#{2,4}\s+/`, the section/preamble forms) so the test tracks the real contract. This finding folds in the duplicate observation that `generate-srd-spells.test.ts` is misnamed (same root cause as the missing `splitIntoBlocks` coverage). Distinct from the seed-parser-edge-branches finding (that targets `parse-spell-block` and the glossary parser, not block segmentation), and related to but narrower than already-filed codebase-audit #22 (helper-dir orientation) — this is a specific module's missing test plus a filename fix, not a directory-level doc. No tooling pins this test by path that would need updating beyond the rename; confirm with a grep for `generate-srd-spells.test` before moving. Low risk: a mechanical rename with no semantic change to the relocated assertions.

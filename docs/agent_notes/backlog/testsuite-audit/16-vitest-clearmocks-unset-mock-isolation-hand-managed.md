# 16. No vitest config enables clearMocks; mock-call-state isolation is hand-managed across ~140 client test files

Status: Proposed — read-only finding from the test-suite audit; NOT implemented. Re-verify file:line before acting.
Lens: defect-catching · Area: test-infra / mock hygiene (client-dominant) · Severity: med · Size: S-M · Confidence: high
Theme: config-enforced test isolation · Source: Musi test-suite audit 2026-06-13 (multi-agent, adversarially verified)

## Problem
Vitest does not reset mock call history between tests unless a config or setup file asks it to, and nothing in this repo does. The root `vitest.config.ts` wires five projects together but sets no `test.clearMocks` / `mockReset` / `restoreMocks`, and none of the per-project configs set them either. The two setup files that could compensate do not: the client `setup.ts` `afterEach` calls only `cleanup()` (React Testing Library DOM teardown), and the server `setup.ts` `beforeEach` only resets the worker DB and the auth rate limiter. So mock-call-state isolation — the guarantee that a `toHaveBeenCalledTimes`/`toHaveBeenCalledWith` assertion sees only *this* test's calls — rests entirely on every author remembering to clear the right spy at the right place.

The numbers show how thin that discipline is on the client, where mocking is heaviest: of 265 test files, 140 call `vi.mock`, but only 48 call `clearAllMocks` and **zero** call `resetAllMocks`. The majority of mock-using client files therefore have no suite-level reset at all. The pattern that leaks is the module-level `vi.fn()` wired into a `vi.mock` factory: it is created once per module and accumulates call history across every `it()` in the file. Authors patch that leak by hand, at scattered sites — `invite-panel.test.tsx` and `campaign-settings-panel.test.tsx` both define a top-level `toastSuccessSpy = vi.fn()` inside a `react-hot-toast` mock factory and then call `toastSuccessSpy.mockClear()` mid-suite specifically so a prior test's toast does not inflate a later `toHaveBeenCalledWith` check. On the server, `auth-middleware.test.ts` runs `vi.resetAllMocks()` in `beforeEach` because its module-level `mockVerify` spy carries `mockResolvedValue`/`mockRejectedValue` state forward between cases.

This is a latent order-dependence hazard, not a today-failing bug: a forgotten clear yields a test that is green only because of the call history a sibling test happened to leave behind, and which flips to a `toHaveBeenCalledTimes` mismatch the moment tests are reordered, filtered, or one is deleted. It is also a standing maintenance tax — roughly 42 client files carry scattered manual `mockClear()`/`mockReset()` calls that exist only to paper over the missing config-level reset.

## Evidence
- `vitest.config.ts:3-47` — root `defineConfig` declares `test.projects` (shared, server, client, eslint-rules, scripts) and coverage thresholds, but sets no `clearMocks`/`mockReset`/`restoreMocks`. A repo-wide grep over all `vitest*.ts` configs returns none of those three flags.
- `packages/client/vitest.config.ts:5-22` — `defineProject` with only `resolve.alias`, `setupFiles`, `include/exclude`, and `coverage`; no `test.clearMocks/mockReset/restoreMocks`. `packages/client/src/test/setup.ts:40-42` — the lone `afterEach` calls only `cleanup()`.
- `packages/server/src/test/setup.ts:44-47` — `beforeEach` awaits `cleanDb()` and `authRateLimiter.reset(...)`; no mock reset.
- `packages/server/src/socket/auth-middleware.test.ts:22-24` — `beforeEach` runs `vi.resetAllMocks()`, required because the module-level `mockVerify` (line 10) retains per-test `mockResolvedValue`/`mockRejectedValue` state set at lines 39, 52, 63, 73, 88, 95.
- `packages/client/src/components/campaign/members/invite-panel.test.tsx:11,12,108,128` — module-level `toastSuccessSpy = vi.fn()` wired into a `react-hot-toast` `vi.mock` factory, with inline `toastSuccessSpy.mockClear()` at lines 108 and 128 to prevent call-count bleed. `packages/client/src/components/campaign/settings/campaign-settings-panel.test.tsx:10-11,111` — same module-level-spy pattern with one inline `mockClear()` at line 111. (Note: this file moved into the `settings/` subdirectory since the finding was captured; the original `campaign/campaign-settings-panel.test.tsx` path no longer exists.)
- Client counts (re-verified at HEAD): 265 test files; `vi.mock` in 140; `vi.fn` in 171; `vi.spyOn` in 21; `clearAllMocks` in 48; `resetAllMocks` in 0; 42 files carry per-mock `mockClear()`/`mockReset()`. Most `vi.mock`-using files have no suite-level reset.

## Proposed direction
Land `test.clearMocks: true` once, at the root `vitest.config.ts`, so it applies to every project. `clearMocks` resets each mock's call history (`mock.calls`, `mock.results`) before every test — exactly the isolation the 48 scattered `clearAllMocks()` calls and the 42 inline `mockClear()` sites are reaching for — without touching the mock's *implementation*. Land the flag first, run the full suite, and confirm it stays green. Then, as a separate follow-up codemod, delete only the now-redundant inline call-history resets: the per-file `clearAllMocks()` and the inline `mockClear()` sites (e.g. `invite-panel.test.tsx:108,128`, `campaign-settings-panel.test.tsx:111`) whose sole purpose was call-history isolation.

Three constraints the cleanup MUST respect — each one protects currently-green tests:
1. Do **not** enable `mockReset`. 48 client files set `mockReturnValue`/`mockResolvedValue`/`mockImplementation` inside (or alongside) their `vi.mock` factories and rely on that behavior persisting across tests; `mockReset` wipes implementations and would silently turn those mocks into no-op `undefined` returns, breaking tests without any signal at the config change.
2. Do **not** remove the `vi.resetAllMocks()`/`mockReset()` reset sites such as `auth-middleware.test.ts:22-24`. Those depend on *implementation* reset (clearing the forwarded `mockResolvedValue`/`mockRejectedValue` between cases), which `clearMocks` does not provide.
3. Keep `restoreMocks` off. The client `setup.ts` intentionally restores its `console.error`/`console.warn` spies in `afterAll` (lines 44-47); `restoreMocks` would detach `vi.spyOn` implementations per-test and fight that lifecycle.

Estimated impact: eliminates a class of latent order-dependence / call-count-bleed defects across ~140 mock-using client files and lets the follow-up codemod remove ~48 scattered manual call-history resets — with isolation enforced by one config line instead of per-author discipline. This is a hygiene/preventive win, not a speed win; no measurable runtime change is expected.

## Scope / caveats
Scope strictly to two steps: (1) add `clearMocks: true` to the root `vitest.config.ts` `test` block; (2) a `mockClear`-only cleanup codemod over the redundant inline call-history resets. Explicitly EXCLUDE `mockReset` and the removal of `resetAllMocks`/`mockReset` reset sites per the three constraints above — an earlier candidate suggestion to enable `mockReset` for the client was evaluated and rejected as unsafe. Do not touch the `setup.ts` console-restore logic.

Sequence matters: land the config flag, verify the suite stays green, *then* run the cleanup codemod — never bundle the flag and the deletions in one change, so any unexpected breakage is attributable.

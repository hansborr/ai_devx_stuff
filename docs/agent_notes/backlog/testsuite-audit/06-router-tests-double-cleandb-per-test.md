# 6. 700+ router tests run cleanDb() twice per test (global beforeEach + redundant helper/per-file clean)

Status: Proposed — read-only finding from the test-suite audit; NOT implemented. Re-verify file:line before acting.
Lens: speed · Area: server · Severity: med · Size: S-M · Confidence: high
Theme: db-isolation-cost · Source: Musi test-suite audit 2026-06-13 (multi-agent, adversarially verified)

## Problem
Every server test already gets a clean database for free. The global setup file registered in `setupFiles` runs `await cleanDb()` in a `beforeEach` that fires before any test in the project (`packages/server/src/test/setup.ts:44-46`, registered at `packages/server/vitest.config.ts:18`). Vitest runs `setupFiles` `beforeEach` hooks ahead of file-level `beforeEach` hooks, so by the time any per-file or per-helper setup runs, the DB is already guaranteed empty. That global hook is the single owner of test isolation.

A large fraction of the router suite then cleans a **second** time for zero added isolation. The per-feature setup helpers each call `cleanDb()` independently before seeding: `setupCampaignTestContext` defaults `options.cleanDatabase ?? true` and runs `cleanDb()` (`packages/server/src/test/campaign-test-context.ts:69-71`), and it is reached per-test through `setupEncounterTestContext` / `setupInventoryTestContext` (and the spell/rest/homebrew helpers each clean directly). On top of that, 20 router test files call `cleanDb()` directly in their own `beforeEach` (26 call sites total). Because the global hook already cleaned, each of these is a pure duplicate pass.

A redundant pass is not cheap: `cleanDb()` issues 22 sequential `deleteMany()` round-trips (`packages/server/src/test/clean-db.ts:12-43` — 3 homebrew, 7 campaign, 10 character, plus `session` and `user`), awaited one after another. Doubling that for hundreds of tests is the single largest avoidable fixed cost on the server critical path. The redundancy is structural and certain; only the wall-clock magnitude is unmeasured (and it grows once tables hold rows, since `deleteMany` cost scales with row count).

## Evidence
- `packages/server/src/test/setup.ts:44-46` — global `setupFiles` `beforeEach` runs `await cleanDb()` before every server test (registered at `packages/server/vitest.config.ts:18`); `setupFiles` hooks fire before file-level `beforeEach` in vitest, so this owns isolation.
- `packages/server/src/test/campaign-test-context.ts:69-71` — `setupCampaignTestContext` does `if (options.cleanDatabase ?? true) { await cleanDb(); }`; the encounter and inventory contexts reach this per-test.
- `packages/server/src/test/encounter-test-helper.ts:23` — `setupEncounterTestContext` calls `setupCampaignTestContext(app)` with no options, so `cleanDatabase` stays `true` (a redundant clean) for every encounter consumer.
- `packages/server/src/test/inventory-test-helper.ts:98`, `spell-test-helper.ts:18`, `rest-test-helper.ts:17`, `homebrew-test-helper.ts:28` — each helper independently calls `await cleanDb()` before seeding.
- `packages/server/src/routers/character.test.ts:30-35` and `character-stats-concurrency.test.ts:36` — files whose own `beforeEach` opens with `await cleanDb()`. Verified count: 20 router test files, 26 `await cleanDb()` call sites (the other 18: `weapon-mastery`, `sorcery-point`, `notification`, `notification-mutations`, `mutation-logging`, `invite`, `invite-manage`, `invite-join`, `invite-concurrency`, `character-updates`, `character-updated-broadcast`, `character-multiclass-level-up`, `character-level-up`, `character-create-transaction`, `character-assignment`, `campaign`, `vault-access`, and the merge-added `seed-read-normalization.test.ts` whose `cleanDb()` is a per-describe `beforeEach` at `routers/seed-read-normalization.test.ts:136`).
- `packages/server/src/test/clean-db.ts:12-43` — a single `cleanDb()` is 22 sequential awaited `deleteMany()` calls; the duplicate pass re-runs all of them.
- Union reaching a redundant second clean (20 direct files + helper consumers: encounter 24, spell 6, homebrew 5, inventory 3, rest 2): 58 distinct test files, ~814 `it()`/`test()` cases. (The original finding cited a conservative ~49 files / ~733 tests; the fresh re-count at HEAD is larger — the claim holds with margin.)

## Proposed direction
Remove only the demonstrably redundant second clean and leave the global `beforeEach` as the sole owner of isolation. Concretely:
- (a) Delete the bare `await cleanDb()` from the 20 router files' own `beforeEach` hooks (those are pure duplicates of the global hook), including the merge-added `seed-read-normalization.test.ts` per-describe `beforeEach` clean.
- (b) Thread `cleanDatabase: false` at the encounter/inventory helper call sites — either have `setupEncounterTestContext` / `setupInventoryTestContext` pass `{ cleanDatabase: false }` into `setupCampaignTestContext`, or accept an options bag and forward it. Do the same for the spell/rest/homebrew helpers' direct `cleanDb()` calls.

Do **not** flip the shared `setupCampaignTestContext` default to `false` globally. `character.test.ts` calls `setupEncounterTestContext` mid-`it()` at 6 sites (`packages/server/src/routers/character.test.ts:472,501,541,568,667,743`) **after** its own `beforeEach` already seeded a user, and there the helper's internal `cleanDb()` is load-bearing — it intentionally wipes that prior user. A blanket default flip would silently break those tests. Likewise the intentional mid-test reset points (`character-stats-concurrency.test.ts:101,289,487`) must stay untouched.

Coverage is unchanged: the global `beforeEach` still cleans before every test, so isolation is identical; only the duplicate second pass is removed. Estimated impact: removes one full `cleanDb()` teardown (22 sequential `deleteMany` round-trips) per test from ~814 tests — single-digit seconds of server wall today, more once rows accumulate, with zero coverage change. The structural redundancy is certain; the exact magnitude is unmeasured, so treat the time figure as directional.

## Scope / caveats
Touch only the 20 router `beforeEach` hooks and the encounter/inventory/spell/rest/homebrew helper call sites. Do **not** alter the shared `setupCampaignTestContext` default, the global `setup.ts` `beforeEach`, or any intentional mid-test reset. The one real risk is a hidden load-bearing helper clean (the 6 mid-`it()` `character.test.ts` sites that re-seed by wiping) — neutralize it by threading the flag at call sites rather than changing defaults. Merged from the pass-1 finding of the same shape ("700 of 1001 router tests run cleanDb() twice per test"); no new claims were added beyond re-verifying counts. The post-merge re-verification (HEAD `692b437a`) left all core target files untouched — `setup.ts`, `vitest.config.ts`, `clean-db.ts`, `campaign-test-context.ts`, the five helpers, and the `character.test.ts` mid-`it()` sites — so every line:line citation above remains exact; the merge only added a 20th router file (`seed-read-normalization.test.ts`) that participates in the same redundant pattern.

This finding is structural (remove redundant calls) and is orthogonal to — but compounds with — a separate cleanDb-internals finding (collapse the 22 round-trips into one `$transaction` / `TRUNCATE`). Either can land first; together they remove both the duplicate-pass cost and the per-pass round-trip cost. Coverage is preserved in all cases because the global `beforeEach` is never modified and still runs before every test.

# 32. Tmp-dir + git-repo test scaffold is reinvented per-file across the entire scripts suite (no shared helper)

Status: Proposed — read-only finding from the test-suite audit; NOT implemented. Re-verify file:line before acting.
Lens: maintainability · Area: scripts/** (cross-cutting test scaffold: drift-ai, drift, lint-ratchet, codemods, harness) · Severity: med · Size: M · Confidence: high
Theme: shared-test-fixture-extraction · Source: Musi test-suite audit 2026-06-13 (multi-agent, adversarially verified)

## Problem
Every scripts test that needs a working directory hand-rolls the same temp-repo lifecycle. The shape is invariant: a module-level `const tempRoots: string[] = []`, an `afterEach` that drains it with `while (tempRoots.length > 0) { const root = tempRoots.pop(); if (root !== undefined) rmSync(root, { recursive: true, force: true }); }`, and a local `writeRepo`/`makeTempRepo`/`makeRepoRoot`/`makeTree`/`makeRepo` builder that calls `mkdtempSync(path.join(tmpdir(), "<prefix>-"))`, pushes onto `tempRoots`, then `mkdirSync`+`writeFileSync`s the requested files. That exact drain loop appears in **37 scripts test files** (21 under drift-ai, 5 lint-ratchet, 5 codemods, 3 harness, plus `drift/locator-usage`, `logs-audit`, `sensor-blob-size`). Within drift-ai specifically, 13 `*.test.ts` files define a `writeRepo(files: Record<string, string>): string` whose body is semantically identical (the bodies differ only in the `mkdtemp` prefix). Within lint-ratchet, `writeBaselineFixture(text)` is verbatim-identical in `lint-ratchet-zero-baseline.test.ts:90-96` and `lint-ratchet-check-registry.test.ts:91-97` (differing only in prefix), and `tempDebtLog` (`lint-ratchet-debt-log.test.ts:16-22`) is the same pattern with a different filename.

This matters because cleanup semantics, `mkdtemp` behavior, and git-init flags now live in dozens of independently editable copies, and they have already silently drifted: the looser `if (root)` truthiness guard appears in roughly a dozen files (~12) versus ~20 using the defensive `if (root !== undefined)` form — `drift/locator-usage.test.ts:21` and `sensor-blob-size.test.ts:15` are representative examples of the looser guard, not the only ones. There is **no** shared scripts test-support TS module (the only `test-support*` file is the unrelated `scripts/ai-hooks/test-support.sh`), and the scripts vitest project declares no `setupFiles`, so the convergence has nowhere to land yet. The gap is confirmed by three drift-ai tests that have already started reinventing their own one-off temp-dir helper (`makeTempDir` in `prototype-subcommands.test.ts:23` and `semgrep-candidates-command.test.ts:22`, `makeTempRoot` in `diagnostics-projection.test.ts:242`) — convergence with no shared home. Because scripts is the repo's lowest-coverage, highest-weighted project (the repo IS the tool), this scaffold noise sits exactly where it costs the most.

## Proposed direction
Add one shared scripts test-support module (e.g. `scripts/test-support/tmp-repo.test-helper.ts`, matching the established `*.test-helper.ts` convention) exporting:
- `registerTempRootCleanup()` — registers a single module-scope `afterEach` drain and returns a push/track handle;
- `makeTempRepo(prefix?)` / `writeRepo(files, prefix?)` — the `mkdtemp` + `mkdirSync`/`writeFileSync` builder;
- `writeRepoFile(root, rel, contents)` — the single-file `mkdirSync`-then-`writeFileSync` helper;
- `makeTmpGitRepo(prefix?)` — `mkdtemp` + `git init -q` for the `sensor-blob-size`-style tests.

IMPORTANT — the afterEach-registration-scope trap: the factory must NOT call `afterEach()` internally from inside an `it()` callback. `writeRepo` is invoked inside test bodies, but vitest requires `afterEach` to be registered at collection/module scope. So expose a module-scope `registerTempRootCleanup()` that each test file calls once at top level; do not self-register the hook from inside the per-call builder.

Adopt incrementally, starting with drift-ai (where `writeRepo` is most uniform across 13 files) and lint-ratchet (`writeBaselineFixture` + `tempDebtLog`), then codemods and harness. This is a pure mechanical extraction: same fs behavior, same `rmSync(..., { recursive: true, force: true })` cleanup semantics, no assertion changes — coverage is fully preserved. Standardizing on the defensive `if (root !== undefined)` guard during migration also retires the `if (root)` drift already present in `locator-usage`/`sensor-blob-size`.

Estimated impact: removes the repeated ~6-line drain plus the bespoke `makeRepo`/`writeRepo` blocks from ~37 files (on the order of 270+ lines of pure fs scaffolding), centralizing temp cleanup so a future leak fix or git-init-flag change is a single edit. No runtime speedup is claimed (the work is fs-bound and unchanged); the win is maintainability and lowering the noise floor in the lowest-coverage, highest-weighted project. Convergence is incremental, so the 37 sites adopt over time rather than in one atomic change.

## Scope / caveats
TOUCH: `scripts/**` test files and a new shared `scripts/test-support` (or `*.test-helper.ts`) module. NOT-TOUCH: any assertion, any production code, the cleanup semantics themselves. RISK: trivial — behavior-identical; the only subtlety is the afterEach-registration-scope trap (do not self-register the hook from inside `it()`). SEQUENCING: land the helper module first, then migrate subdirs incrementally (drift-ai → lint-ratchet → codemods/harness); does not need to be atomic.

BOUNDARY: this finding **merges three same-issue candidates** — (a) the cross-cutting scripts tmp-dir/git-repo scaffold, (b) the drift-ai `writeRepo` + `tempRoots` + `afterEach` duplication, and (c) the lint-ratchet `writeBaselineFixture` + `tempRoots`/`afterEach` `rmSync` scaffold — because they all converge on one shared temp-repo module and would be fixed together. It is DISTINCT from the codemod fixture-runner finding (a ~110-line validator + fs-compare harness, well beyond a tmp dir) and from the drift-ai GitRunner-stub and lint-ratchet `LintRatchetConfig`-fixture findings (those are domain-specific builders, not the generic temp-repo idiom). It is also not covered by any prior scaffold slug — `router-tests-double-cleandb-per-test`, `socket-tests-duplicate-seed-and-joinroom`, and `client-tests-hand-roll-queryclient-wrapper` all concern server/client/socket/router/page scaffolds; none touch the scripts tmp-dir/git-repo idiom.

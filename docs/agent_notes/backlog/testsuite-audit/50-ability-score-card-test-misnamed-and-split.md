# 50. sheet/ability-score-card.test.tsx is misnamed — it tests AbilityScores, splitting that component across two files and colliding with the char-create test basename

Status: Proposed — read-only finding from the test-suite audit; NOT implemented. Re-verify file:line before acting.
Lens: maintainability · Area: client · Severity: low · Size: XS · Confidence: high
Theme: test-orientation · Source: Musi test-suite audit 2026-06-13 (multi-agent, adversarially verified)

## Problem
`packages/client/src/components/sheet/ability-score-card.test.tsx` is named after `ability-score-card.tsx`, but it imports and tests `AbilityScores` (from `./ability-scores.js`) — the parent grid component, not the `ReadOnlyScore`/card helper its filename advertises. The card is only exercised transitively: `ability-scores.tsx` pulls in `ReadOnlyScore` from `./ability-score-card.js` and renders it per ability, so the "card" file has no direct test of its own.

The practical cost is twofold. First, `AbilityScores` coverage is split across two confusingly-named siblings in the same directory: `ability-score-card.test.tsx` holds the read-only-render and click-to-roll cases, while `ability-scores.test.tsx` holds the DM edit/save/cancel/CAS cases. A dev grepping for where `AbilityScores` roll behavior is tested finds a file named after a *different* component, and there is no single obvious home for the component's tests. Second, the misnamed file shares its basename with `character-create/steps/ability-score-card.test.tsx`, which genuinely tests an `AbilityScoreCard` component plus point-buy helpers (`calcModifier`, `computeBoosts`, constants) — so two files named `ability-score-card.test.tsx` test entirely different things, and a basename search returns both with no way to tell which is which. This is a discoverability/onboarding tax, not a correctness bug: every test runs and passes today; they are simply filed under the wrong name.

## Evidence
- `packages/client/src/components/sheet/ability-score-card.test.tsx:8` — `import { AbilityScores } from "./ability-scores.js";` — the filename says "card" but the import (and every case) targets `AbilityScores`.
- `packages/client/src/components/sheet/ability-score-card.test.tsx:23,53` — `describe("AbilityScores read-only rendering", …)` and `describe("AbilityScores click-to-roll", …)` — both blocks name `AbilityScores`, confirming the subject mismatch.
- `packages/client/src/components/sheet/ability-scores.test.tsx:23` — `describe("AbilityScores DM edit toggle", …)` (plus batch save :82, async DM save :160, cancel :214, expectedVersion CAS :234) — same component, exercised in a separate file, so `AbilityScores` coverage is split.
- `packages/client/src/components/sheet/ability-scores.tsx:13` — `import { ReadOnlyScore } from "./ability-score-card.js";` (rendered at :127) — confirms the card is reached only transitively through `AbilityScores`, so the card file has no direct test.
- `packages/client/src/components/character-create/steps/ability-score-card.test.tsx:148` — `describe("AbilityScoreCard", …)` alongside helper blocks `describe("calcModifier")` (:23), `describe("computeBoosts")` (:61), `describe("constants")` (:94) — a genuinely different `AbilityScoreCard` component sharing the exact same test basename.

## Proposed direction
Pure rename/move, no assertion changes. Either (a) rename `sheet/ability-score-card.test.tsx` to reflect its real subject — e.g. `sheet/ability-scores.roll.test.tsx` — so it sits next to `ability-scores.test.tsx` and reads as "the roll/read-only slice of AbilityScores"; or (b) merge its two `describe` blocks into `sheet/ability-scores.test.tsx` so `AbilityScores` has a single obvious test home. Either option ends the basename collision with `character-create/steps/ability-score-card.test.tsx`. Verify with `bun run test -- packages/client/src/components/sheet/ability-scores.test.tsx` (and the renamed file, if kept separate); the same `it()` count must pass with zero assertion edits. Estimated impact: no run-time change (same cases run), but it removes a name/subject mismatch and a cross-directory basename collision, so `AbilityScores` tests live in one obviously-named place and a basename search no longer returns two unrelated files.

## Scope / caveats
XS, coverage-preserving, client-only — touch only the test file name/location (and `ability-scores.test.tsx` if merging). Do **not** add new direct tests for the presentational card helpers (`Modifier`/`RollableCard`/`ReadOnlyScore`): their transitive coverage through `AbilityScores` is normal and intentional, and adding card-level tests is out of scope here. If you choose the merge option, watch for the overlapping `describe("AbilityScores …")` block names across the two files (e.g. avoid duplicate "read-only" headings) and keep block names distinct. This is a naming/discoverability finding, not a duplication or dead-code finding — nothing is unused and no assertions are duplicated. It is distinct from codebase-audit #34 (`resolveSavingThrow` tests misplaced inside `combat.test.ts`); that is a different file and a cross-source misplacement, whereas this is a same-directory misnaming plus a cross-directory basename collision. No sequencing dependency on other findings; safe to land standalone.

# 52. VTT drawer page object hardcodes CELL_SIZE_PX=40, silently coupled to the client's frozen default grid cell size

Status: Proposed — read-only finding from the test-suite audit; NOT implemented. Re-verify file:line before acting.
Lens: maintainability · Area: e2e · Severity: low · Size: XS · Confidence: med
Theme: magic-constant · Source: Musi test-suite audit 2026-06-13 (multi-agent, adversarially verified)

## Problem
`vtt-drawer.po.ts` translates logical grid cells into Konva canvas click coordinates with `(cell + CELL_CENTER_OFFSET) * CELL_SIZE_PX`, where `CELL_SIZE_PX` is hardcoded to `40`. That `40` is a duplicate of the client's `DEFAULT_CELL_SIZE_PX = 40` in `map-canvas-store.ts`, which is the real source of truth for the rendered grid cell size. The two constants are linked only by an unwritten contract: there is no comment, import, or shared symbol tying the page object's `40` back to the store's `40`.

The page object is a black box over the wire (it clicks pixel positions inside a single Konva `<canvas>`), so the coupling is invisible until it breaks. Every token-interaction path in `encounter-combat.spec.ts` routes its grid clicks through the private `clickCell` / `openTokenContextMenu` helpers, which means if someone changes the client default cell size, every one of those clicks lands on the wrong cell. The failure surfaces as a confusing "wrong target / no token here" symptom across the whole spec rather than pointing at the magic `40` that actually drifted. The constant has no breadcrumb back to its origin, so a maintainer changing the grid size has no way to know this test file needs to move in lockstep.

## Evidence
- `e2e/page-objects/vtt-drawer.po.ts:5,7` — `const CELL_SIZE_PX = 40;` and `const CELL_CENTER_OFFSET = 0.5;` are declared as bare module-level constants with no comment linking `40` to its client source.
- `e2e/page-objects/vtt-drawer.po.ts:199-203` — `clickCell` computes `position.x = (cell.x + CELL_CENTER_OFFSET) * CELL_SIZE_PX` (and `.y`), then calls `this.konvaContent.click({ button, position })`; this is the single chokepoint that converts a logical `Cell` into a pixel click.
- `packages/client/src/stores/map-canvas-store.ts:8` — `const DEFAULT_CELL_SIZE_PX = 40;` is the actual source of truth; `:202` seeds `INITIAL_STATE.cellSizePx: DEFAULT_CELL_SIZE_PX`.
- `packages/client/src/stores/map-canvas-store.ts:299-300` — `setCellSizePx` is the only writer of `cellSizePx`; a repo-wide search finds no non-test caller (only the interface declaration at `:130`, this implementation, three calls in the store's own unit test `map-canvas-store.test.ts:98,364,405`, and two `vi.fn()` mocks in `map-detail-view.test.tsx` / `combat-map-panel.test.tsx`), so the rendered cell size is effectively frozen at `40` today — all callers are test-only, so the "no non-test caller" conclusion is unchanged.
- `e2e/encounter-combat.spec.ts:340-439` — across this spec's 18 leaf `test()` blocks (one `test.describe`), 11 public-method calls depend on cell→pixel math: `openSheetFromToken` (×7), `expectNoOpenSheetForToken` (×1), `attackWithWeapon` (×1), `castSingleTargetSpell` (×1), `castAoeSpell` (×1) — and several of those (e.g. `castAoeSpell`) call `clickCell` more than once internally, so the underlying coordinate-dependent click count is higher than 11. (The merge-added "sheet-side HP adjust" test uses the standalone `CharacterSheetPO` and adds no coordinate-dependent clicks.)

## Proposed direction
Add a one-line comment on `CELL_SIZE_PX` in `vtt-drawer.po.ts:5` that names its source of truth — `DEFAULT_CELL_SIZE_PX` in `packages/client/src/stores/map-canvas-store.ts` — so a future grid-size change is traceable and a maintainer editing the client default knows to mirror it here. This is the only sound, coverage-preserving fix: it changes no assertion, no click math, and no test behavior, so coverage of token interactions is unchanged. Estimated impact: makes the coordinate math self-documenting and converts a confusing whole-spec failure mode (every cell click misses) into a one-grep-away fix if the client grid size ever changes; no runtime/speed change.

## Scope / caveats
Touch only the comment on `CELL_SIZE_PX` in `vtt-drawer.po.ts`; do not touch `clickCell`, the spec, or any client source. Stakes are genuinely low because the coupled value is effectively frozen — `setCellSizePx` has no non-test caller, so the rendered cell size is `40` at runtime today and the failure mode is conditional on an edit that does not happen. That is also why confidence is `med` rather than `high`: the coupling is real and undocumented, but the trigger does not exist in the current tree.

Two anti-patterns to explicitly avoid. Do NOT try to "derive the cell size at runtime from the canvas bounding box or a data attribute": the map renders as a single Konva `<canvas>` (`konvaContent` is the `presentation`-role element) with no per-cell DOM and no exposed cell-size attribute, so runtime derivation is not feasible. Do NOT import the client `DEFAULT_CELL_SIZE_PX` constant into the Playwright layer — the e2e suite deliberately treats the app as a black box over the wire and must not reach into `packages/client/src`. The one-line comment is the correct scope. This is a magic-constant/traceability finding, not a duplication or dead-code finding (those are owned by `docs/agent_notes/backlog/drift-ai-findings/`); the duplicated literal stays, it just gains a breadcrumb.

# 48. Homebrew *-form-fields tests inline the verbose 3-prop render call 6–19 times per file instead of a renderFields helper

Status: Proposed — read-only finding from the test-suite audit; NOT implemented. Re-verify file:line before acting.
Lens: maintainability · Area: client · Severity: low · Size: S · Confidence: high
Theme: render-scaffold-consistency · Source: Musi test-suite audit 2026-06-13 (multi-agent, adversarially verified)

## Problem
Six of the nine homebrew `*-form-fields.test.tsx` files (seven render a component; the other two — spell and feat — are data-helper-only) render their component under test by inlining the full three-prop call — `render(<XFormFields form={makeForm()} onChange={vi.fn()} fieldErrors={{}} />)` — on essentially every test case. The repetition ranges from 6 calls (species) up to 19 (class), with no per-test variation in two of the three props: `onChange` is almost always a throwaway `vi.fn()` and `fieldErrors` an empty `{}`. The only thing that meaningfully varies between cases is the form data (`makeForm({ ... })`), an occasional `fieldErrors` map, and — for the payload tests — whether the `onChange` spy is captured for assertion.

The sibling `subclass/subclass-form-fields.test.tsx` already demonstrates the cleaner shape: a local `renderFields(overrides?)` helper that defaults the three props, renders, and **returns the props object** so callers can pull the captured spy back out (`const { onChange } = renderFields()`). Tests there read as `renderFields({ fieldErrors: { name: "Name is required" } })` — only the delta is visible. The other six never adopted this; instead, a test that needs to assert on `onChange` declares `const onChange = vi.fn()` and then restates the whole spread by hand (e.g. monster lines 93–94), so the noise actively obscures what each case is really exercising.

This is a maintainability/onboarding wart, not a correctness or coverage gap: the disabled-when-N-selected, onChange-payload, and conditional-field show/hide assertions are all fine. The cost is that the family is inconsistent (one file has the helper, six don't), and any future column added to the component's props means editing dozens of identical render lines across six files instead of one helper each.

## Evidence
- `packages/client/src/components/homebrew/subclass/subclass-form-fields.test.tsx:9-18` — the `renderFields(overrides?: Partial<Parameters<typeof SubclassFormFields>[0]>)` helper: defaults `form`/`onChange`/`fieldErrors`, renders via `renderWithProviders`, and `return props` so spies stay capturable. The only file in the family with it.
- `packages/client/src/components/homebrew/background/background-form-fields.test.tsx:14` — `render(<BackgroundFormFields form={makeForm()} onChange={vi.fn()} fieldErrors={{}} />)` inlined; this file repeats it 13 times. Note it imports bare `render` from `@testing-library/react` (line 1), not `renderWithProviders`.
- `packages/client/src/components/homebrew/monster/monster-form-fields.test.tsx:93-96` — representative payload test: `const onChange = vi.fn()`, then re-inlines the full spread with `onChange={onChange}`, then `expect(onChange).toHaveBeenCalledWith(...)` — exactly the case `renderFields`'s returned-props design exists to collapse.
- Verified inline render counts (per file): class 19, monster 17, background 13, magic-item 11, item 7, species 6. None of the six currently defines a `renderFields` helper (`function renderFields|const renderFields` count = 0 in all six); all six use a local `makeForm(...)` wrapper over the corresponding `getDefault*Data` and bare `render` from `@testing-library/react`.
- `packages/client/src/components/homebrew/spell/spell-form-fields.test.tsx:1-3` and `feat/feat-form-fields.test.tsx:1-3` — correctly outside the six: despite the `-form-fields` name, these import and exercise only data helpers (`getDefaultSpellData`/`buildSpellData`, `getDefaultFeatData`/`buildFeatData`) and render no component, so they have no spread to collapse.

## Proposed direction
Pure scaffolding refactor: give each of the six files a local `renderFields(overrides?: Partial<Parameters<typeof XFormFields>[0]>)` helper modeled on the proven subclass one — default `form: makeForm()`, `onChange: vi.fn()`, `fieldErrors: {}`, render, and `return props` — then collapse the inline calls. Cases that vary nothing become `renderFields()`; error cases become `renderFields({ fieldErrors: { ... } })`; payload cases become `const { onChange } = renderFields()` so the spy is recovered from the returned props instead of being declared and threaded by hand. The disabled-when-N-selected, onChange-payload, and conditional show/hide assertions stay byte-for-byte identical.

One implementation nuance carried from re-verification: the six use bare `render` while subclass uses `renderWithProviders`. Keep each file on its current render function inside its helper (i.e. the helper wraps whatever that file already calls); do not silently switch the six to `renderWithProviders` as part of this — that would be a behavioral change to the test environment, out of scope here.

Estimated impact: removes ~70+ repeated render lines across the six files (sum of the 6–19 counts, minus one helper each) and makes every test show only its delta. No runtime/speed change — this is readability and single-point-of-edit, not perf.

## Scope / caveats
Touch only the six `*-form-fields.test.tsx` files (background, class, monster, magic-item, item, species); leave `subclass` (already correct), `spell`, and `feat` (data-helper tests, no component render) alone, and touch no component source. Size S, low risk, no flakiness or coverage stakes: every assertion is preserved verbatim and pass counts must stay identical per file. Adopt the subclass `renderFields` signature exactly so the returned-props spy-capture idiom carries over. This is a test-ergonomics/consistency finding and is distinct from the drift-ai duplication findings (#24/#26/#27, which cover server/vtt helper dups) — no production code is duplicated or unused here. Bottom-of-bar, but a quick, self-contained family-wide consistency win that can land independently of any other finding.

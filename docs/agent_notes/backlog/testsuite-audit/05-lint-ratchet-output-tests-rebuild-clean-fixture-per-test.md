# 5. lint-ratchet output tests rebuild a byte-identical clean+seeded fixture (full tree copy + `bun --update` cold start) once per read-only test

Status: Proposed — read-only finding from the test-suite audit; NOT implemented. Re-verify file:line before acting.
Lens: speed · Area: scripts/lint-ratchet/lint-ratchet-output.test.ts · Severity: med · Size: S-M · Confidence: high
Theme: redundant-per-test-setup · Source: Musi test-suite audit 2026-06-13 (multi-agent, adversarially verified)

## Problem
The `describe("lint ratchet diagnostics output file")` block (`lint-ratchet-output.test.ts:296-366`) has five `it()` cases, and each one independently rebuilds the single most expensive fixture in the tooling test suite from scratch. Every case calls `makeFixture()` and then `seedCleanBaseline()` before its own body even starts.

`makeFixture()` (lines 198-216) is not cheap: it `cpSync`-copies the entire derived runtime module set (`deriveLintRatchetRuntimeModules()` + `CROSS_DIR_RUNTIME_FILES`) into a fresh temp dir, writes four fixture files (package.json, eslint.config.js, the minimal ratchet config, and clean `example.ts`), double-symlinks two `node_modules` trees, and — via `initializeFixtureGitIndex` (lines 193-195) — runs `git init -q` plus `git add -A` as subprocesses. `seedCleanBaseline()` (lines 246-248) then spawns a full `bun run scripts/lint-ratchet.ts --update` cold-start subprocess just to write the baseline. After all that setup, each `it()` spawns at least one more `runLintRatchet` cold-start subprocess to exercise the actual behavior.

There is no `beforeAll` or `beforeEach` sharing in the file at all — only an `afterEach` that tears the temp roots down (lines 259-264). So the block performs 5 `makeFixture()` calls and 10 `bun` cold-start subprocesses (5 `seedCleanBaseline` + 5 in-body runs). Critically, four of the five tests build a *byte-identical* clean+seeded fixture and differ ONLY by the env var / args they pass and the output file they read; just the fourth case (`"writes the envelope before exiting non-zero for findings"`, lines 341-354) mutates the fixture via `writeDebugSource`. This is the slowest tooling test file in the repo and every one of those `it()` cases carries a 15s timeout, so the redundant rebuild is paid five times over against the suite's longest budgets.

## Evidence
- `scripts/lint-ratchet/lint-ratchet-output.test.ts:198-216` — `makeFixture` `cpSync`-copies the full derived runtime module set + `CROSS_DIR_RUNTIME_FILES`, writes four fixture files, double-symlinks two `node_modules` trees, and (via `initializeFixtureGitIndex`, lines 193-195) runs `git init -q` + `git add -A` per call.
- `scripts/lint-ratchet/lint-ratchet-output.test.ts:246-248` — `seedCleanBaseline` spawns a full `bun run scripts/lint-ratchet.ts --update` cold-start subprocess per test.
- `scripts/lint-ratchet/lint-ratchet-output.test.ts:301,317,330,342,357` — exactly five `makeFixture()` calls; paired with five `seedCleanBaseline` calls (302,318,331,343,358) and five in-body `runLintRatchet` calls (305,321,334,347,361) = 10 `bun` cold-start subprocesses in the output block.
- `scripts/lint-ratchet/lint-ratchet-output.test.ts:341-354` — only this 4th case mutates the fixture (`writeDebugSource` at 344); the other four are read-only and differ only by env/args.
- `scripts/lint-ratchet/lint-ratchet-output.test.ts:303,319,324` — Test 1 writes `diagnostics.json` into the fixture root (303); Test 2 reuses the SAME path variable (319) and asserts it does NOT exist (`existsSync(outputPath)` is `false` at 324), so a naive shared fixture without per-test output isolation would silently break Test 2's negative-existence assertion.
- `scripts/lint-ratchet/lint-ratchet-output.test.ts:259-264` — only an `afterEach` cleanup exists; a file-wide grep finds zero `beforeAll`/`beforeEach`, confirming no fixture sharing.

## Proposed direction
Build ONE shared clean+seeded fixture in a `beforeAll` for the four read-only output tests (they vary only by env/args and read `result.stdout` plus their own output file), and keep the `writeDebugSource` case on its own throwaway fixture (build it inline in that `it()`, or reset `example.ts` in a `try/finally`).

To preserve coverage exactly, the required correctness step is that each read-only test must read/write a UNIQUE output filename, so Test 2's negative-existence assertion stays meaningful. Test 1 already uses `diagnostics.json`, Test 3 `empty-output.json` (line 332), and Test 5 `new/nested/diagnostics.json` (line 359); Test 2 must assert the absence of its OWN distinct path (e.g. a name no other test writes), not the path Test 1 wrote. Without that, sharing the fixture would either make Test 2 see Test 1's leftover file (false negative) or pass by accident depending on ordering. Keep the `afterEach` so the writeDebugSource fixture and the shared fixture are both torn down.

Estimated impact: removes ~3 fixture-tree copies (each a `cpSync` of the runtime module set + two `git` subprocesses) and ~3 `bun --update` cold-start subprocesses from the slowest tooling test file (the 5 current output-block fixtures collapse to 2: one shared read-only fixture for tests 1/2/3/5 + one isolated `writeDebugSource` fixture for test 4, so 5 − 2 = 3 are removed). Every removed subprocess is a `bun` cold start measured against a 15s budget; expect roughly 3-4s off this file's wall time with no coverage loss. Tooling-weighted value: `scripts/**` carries the repo's lowest coverage thresholds, so trimming its slowest file is above-baseline.

## Scope / caveats
Touch only `scripts/lint-ratchet/lint-ratchet-output.test.ts`. Risk: a naive shared `beforeAll` BREAKS Test 2 unless the read-only tests are first made to use per-test-unique output paths — this is the mandatory correctness step, not an optional polish. The `writeDebugSource` case (341-354) MUST stay on an isolated fixture so its `debugger;` mutation never corrupts the shared clean seed the other four depend on. Preserve the `afterEach` cleanup (259-264) and the per-test 15s timeouts. The three `"fixture runtime file derivation"` tests (266-294) are pure in-process assertions that never call `makeFixture()`/`runLintRatchet`, so they are untouched by this change.

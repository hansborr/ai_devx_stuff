| Give `use-weapon-roll.ts`'s `isNatural20` the `notation.includes("d20")` gate that `roll-toast.ts`'s `detectCrit` has | The asymmetry is deliberate and was left in place by the slice-D panel (`0174e251`, `acb7ac75`). `detectCrit` receives arbitrary rolls, so it must ask whether the roll was a d20 at all; `isNatural20` receives only what `equipment-summary.tsx:94` produces, and that hardcodes `1d20${modifier}`. Adding the gate would be behaviour-identical today and its failure mode is *silent* — a future non-d20 attack die would simply stop critting, with nothing saying why. The premise is pinned producer-side instead (`equipment-summary.test.tsx`), so it fails at the point it is broken. **The latent gap the gate would close is real but unreachable**: were a non-d20 attack die introduced, damage would double without a NAT badge. | Convert `PROFICIENCY_BONUS_TABLE` or the three cantrip tables to a clamp-then-formula | **Refuted permanently by [SHARED-CLUSTER-PLAN.md](./SHARED-CLUSTER-PLAN.md); this is leaf 20's own headline and it is wrong.** `docs/guides/change-rules-logic.md:21-23` mandates the table form for transcribed SRD rules, and the conversion is not behaviour-preserving: `proficiencyBonus(21)` returns `2` today and `6` under `2 + Math.floor((level - 1) / 4)`. The tables *are* the out-of-range guard. The cantrip tables additionally cannot receive an SRD citation — they are keyed on `CasterType`, and the 2024 SRD's class-specific counts differ. |
| Rename `twoHandedDice` to `versatileDice` in any writer or persisted schema | They are the storage spelling and the rules spelling of one concept, with exactly one declared adapter (`enrichFromSrd`) between them, and that contract is now a comment at the seam. Zod strips unknown keys, so removing `twoHandedDice` from `weaponPropertiesSchema`, `equipmentWeaponDataSchema` or `homebrewWeaponDisplaySchema` erases it from every legacy row at read time; the homebrew form's `buildWeaponData` rebuilds the whole payload from its own model, so it writes that erasure back. Leaf 19 steps 3-4 propose exactly this and are **not scheduled**. |
| Derive `ACTION_ECONOMY_CONFIG`'s `field` from `ActionEconomyState` | `ActionEconomyState` is three independent booleans and encodes no `action → actionUsed` relation, so there is nothing to derive from. Doing it would mean inventing a new shared export to serve one client component. Leaf 26 step 3's action-economy half is dropped for this reason. |
| Call a rules-facing slice complete without classifying its provenance and naming any non-SRD policy in the tests | `docs/guides/change-rules-logic.md:7-10` and `:42-45` already require this, but slice E2 still initially missed it. | Call a "make the doc true" slice complete after checking only the claims the leaf cited, or review only the changed words of an edited factual claim | S1 needed three rounds because each review widened the audit surface: the first implementation fixed the cited claims, post-implementation review found another false statement, and the pre-merge panel found three more. The client landing then supplied the sharper case: two false MODULE claims were inherited, but one branch edit rewrote a vaguer true claim into a more specific false one. **Editing a factual documentation claim makes the whole claim yours**, not only the phrase in the diff. A slice whose payoff is document truth must verify every factual claim in that document; any other slice must at least verify every claim it materially edits. |
| Add `characterSpell` to `RestrictedDelegates` and the two `GATED_DELEGATES` copies now that the prepared-spell toggle is transaction-safe | Leaf 51 considered it (its step 3) and refused it deliberately. The fix is transaction-local, so gating the delegate bans direct writes repo-wide and leaves one guarded caller against a dozen ordinary writers — worse than no gate. `docs/CONCURRENCY.md` §Scope also still classes the spell list as a single-writer, non-candidate table. Re-open this only with the whole call-site inventory in hand, which is what the leaf asked for and nobody has produced. |
| Simplify `isPrismaSerializationFailure` (`packages/server/src/utils/prisma-errors.ts`) to the `P2034` check, or replace the retry-shape tests with unit tests that hand-roll the adapter's error | **Both branches are live, and the second one is the common prepared-toggle case.** Under `@prisma/adapter-pg` a statement-level abort maps to P2034, but an abort raised at an interactive `COMMIT` — which is where SSI usually reports anti-dependencies — is re-rejected as a bare `DriverAdapterError` with `cause.kind === "TransactionWriteConflict"` and no `code`. Measured 17:1 in favour of the un-coded shape on a four-way prepared-toggle race. A P2034-only predicate handled long rest's measured statement-level abort but missed that commit-time half. `serializable-isolation.test.ts` pins both shapes against the *real* driver on purpose — hand-rolled shapes would stay green through an upstream rename while production stopped retrying. |
| Restore any wording that says Postgres SSI protects long rest against a concurrent `performLevelUp`, or restore `resetAllHitDice` as the universal barrier | Both are false. `performLevelUp` runs READ COMMITTED, and SSI tracks anti-dependencies only between two serializable transactions. The universal conflict is first-updater-wins on the pre-existing `CharacterStats` row, which both paths keep as their first write before dependent writes. A multiclass `CharacterClass` row is INSERTed after long rest's snapshot and is invisible to `resetAllHitDice`; the post-snapshot spell-slot INSERT is likewise invisible and survives. `packages/server/src/utils/serializable-isolation.test.ts` pins the long-rest abort point, the level-up Stats → CharacterClass order, and the concrete no-stats counterfactual state — change those tests before changing this mechanism. |
| Hand-list the relation names in `local/concurrency-guard` or the runtime nested-write guard, or drop model/context tracking as over-engineering | The leaf's own hand-list was wrong. One generated artifact now carries the relation subgraph that can reach a gated model, its targets, envelope keys, and envelope-name scalar collisions into both consumers. The context is load-bearing: without model identity, `Spell.classes` is misread as a relation; without wrapper-vs-data state, `Notification.data` JSON shaped like a Prisma payload was reproduced as both a hard lint error and a potential production 500. `concurrency-guard-drift.test.ts` and the generator tests fail schema/artifact drift. FK ownership and inverse pairing stay deleted until connect-style policy has a consumer. |
| Expand the nested-write runtime guard to create/delete/connect-style operators, or add a bypass, environment switch, telemetry/config surface, or raw client factory | Leaf 60 is low-severity defense in depth, not an adversarial security boundary. v1 deliberately matches the existing four update/upsert operations. `connect`/`disconnect`/`set` need a separate ownership-aware policy decision and validated ownership derivation: `Character.classes.connect` writes the gated FK-owning `CharacterClass`, while `MapToken.encounterParticipant.connect` writes the non-gated source. Create/delete variants remain outside current policy. The mandatory factory, structural programmer error and schema-bounded walk are the smallest closure for the documented helper/spread/multi-hop update escapes; widening or bypass machinery adds production risk without evidence. Prisma CLI and raw SQL remain explicit external boundaries. |
| Retype the service and utility contexts as `{ req: { server: FastifyInstance } }` | The obvious refactor and the wrong one: it re-couples seven `services/` files and two `utils/` files to Fastify, and `packages/server/src/services/inventory-service.ts:52-55` states that the narrow shape exists so services stay callable from tests without a full Fastify request. 18 test contexts pass `server: {}` and two pass `undefined`; all 20 become type errors. Both server consults rejected it unprompted, and slice S2 landed the `BroadcastHost` port (`packages/server/src/socket/socket-types.ts`) instead, which recovers the types without importing Fastify into a single service file. |
| Trim the `packages/server/src/utils/*-mutations.ts` headers against `docs/CONCURRENCY.md` | A file-local numbered helper-selection guide, a cross-cutting concurrency doc and a per-function JSDoc are three altitudes of one contract, not three copies of it. Leaf 45 step 4 is refused permanently: its own caveats then exempt most of what it proposes to cut, the downside of a wrong trim is a lost concurrency invariant, and the upside is 60 lines of prose in files nobody reads for length. One consult called these "the highest-value comments in the server". |
| Rename `w`/`h` in `packages/shared/src/map/fog.ts` | Persisted `FogLayerData`. | Remove the `packages/server/src/routers/encounter.ts:192-193` casts by making `isValidTransition` a type guard | A TS type predicate narrows only the parameter it names, so `from is …` cannot narrow `input.to`. A helper returning `{ from: EncounterFromState; to: EncounterToState }` is the same 3×3 cross product the file header already misdescribes, so it would drop the casts while leaving the false claim just as false. Both routes fail; the casts stay, they are correctly marked `interop`, and S14 makes the header honest instead. |
| Write or keep a scanning guard that can pass when its scan finds nothing, or one that discovers its subjects from the same allowlist it then compares against | **A scanning guard must assert that it found something, and must discover by pattern rather than by an allowlist it also compares against.** `eslint-rules/socket-registry-broadcasts.test.js` compared the rule's event inventory against the keys it scraped out of `broadcast-registry.ts`, but keyed its scanner on the literal name `BROADCAST_REGISTRY`. When slice S4 split that into `ROOM_BROADCAST_REGISTRY` and `USER_TARGETED_BROADCAST_REGISTRY` the scanner matched nothing, the inventory went empty, and the guard stayed green through exactly the change it exists to catch — nothing in the branch failed. Two properties fix it and both are needed: discovery by pattern (every `*_BROADCAST_REGISTRY` declaration), so a registry the guard was never told about is still found; and a non-empty assertion per discovered subject, so "the source was renamed" cannot be reported as "the inventory is empty". Discovering *from* the allowlist would have reproduced the same failure one level up. The same shape passes vacuously wherever a test derives both sides of a comparison from one fixture, or loops over a scanned corpus with no length guarantee elsewhere in the same forced gate — see [leaf 65](./65-vacuous-scanning-guards.md) for the live instance and the `eslint-rules/` survey. Do not duplicate non-empty assertions when dynamic imports and a companion disk-versus-registry guard already make emptiness fail in that gate, as with leaf 70's broadened helper-collision scan. The surviving direct concurrency corpus carries non-empty assertions in both consuming projects; leaf 60 retired the nested codemod, restored the former parity corpus as lint-only coverage, and replaced cross-detector parity with generated-graph freshness and non-empty topology assertions. |
| Treat `FastifyInstance extends BroadcastHost` — or any `X extends Port` assertion over an all-optional port — as proof that the seam is pinned | It is vacuous. Every member of `BroadcastHost` is optional by design (18 test contexts pass `server: {}`), so `Record<never, never>` satisfies it and *no* object can ever fail the assertion. The pre-merge panel on merge `672cef373` also showed what that hides: a decorator rename applied **consistently** across the augmentation, `IO_DECORATOR_KEY` and the `decorate` call type-checks cleanly while `getSocketIO` reads a member nothing decorates — every broadcast dies silently, which is leaf 02's own headline failure. The catcher is an identity assertion against the augmented instance's member, `Equal<BroadcastHost["io"], FastifyInstance["io"]>` (`packages/server/src/socket/__type-tests__/broadcast-host.ts`), empirically re-proved to be the only assertion in that file the consistent-rename mutation fails. **Any future structural port over an optional-member interface needs the same identity assertion; assignability is not a guard.** |
| Plan "export the type first, adopt it later" as two separate commits | **A new export and its first consumer must land in the same commit.** The `knip-unused-exports` slot (`scripts/sensor-knip-unused-exports.ts`) runs on every pre-commit and in all three `verify` modes, and it fails a commit that adds an export nothing consumes. Slice S8 scheduled exactly that shape — commit 1 exports `AuthzCallerContext` and nothing else, commit 4 narrows the union onto it — and commit 1 is unlandable, because nothing can consume the interface until the union is gone. The two were merged and the alias was deleted outright rather than re-pointed. This is not specific to types: any slice that stages a new `export` ahead of its adopter hits it. **When ordering matters for a different reason, order the *adopters* instead** — S8's real constraint was that the call sites had to move off the string arm before the narrowing, and that survived intact as its own commits. Do not re-derive this from a failing gate. |
| Derive a destructive statement's allowlist from a module that *parses* the same names, or treat the resulting duplicated alphabet as debt to collapse later | **A guard in front of a destructive statement must own its own alphabet and bounds. It may share only *identity* constants, because a module that parses input is allowed to grow more permissive and a module that authorises deletion is not.** Slice S9 was written the other way — export composable fragments from `packages/server/src/test/test-database-url.ts` and derive the `DROP SCHEMA IF EXISTS "public" CASCADE` guard's literals from them — and landed that way first (`38acb0887`). Review demonstrated the failure concretely: widening the *parser's* slug alphabet to admit hyphens, a change no test objects to, made `musi_wt_payroll-prod_test` pass `assertSafeTestDbUrl` and become droppable, with the suite green. The permissiveness a parser may legitimately acquire is exactly the permissiveness a delete authorisation may not. The reversal (`ce7f17da7`, `278bfd94d`) gave **both** destructive statements their own copy — `DROP SCHEMA` in `test/prepare-test-db.ts` and `DROP DATABASE … WITH (FORCE)` in `test/worker-test-database.ts` — sharing only `DEFAULT_TEST_DATABASE_NAME` and `WORKTREE_DB_PREFIX`, which say *which* databases are ours rather than *what* a legal name may contain; `WORKER_KEY_PATTERN_SOURCE` is no longer exported. A confirm round fuzzed both predicates against `main` (400k and 600k cases) with zero divergence, so the duplication cost no behaviour. **The duplication is the boundary — do not re-file it as a single-sourcing leaf.** Where single-sourcing *is* right is toward the producer: `scripts/worktree-db-naming-constants.test.ts` pins `scripts/worktree-db.sh`'s `SLUG_MAX_LEN`, `WORKER_KEY_MAX_LEN` and producer alphabet against the allowlist bounds, which is the direction drift actually travels. |
| Call a value or schema single-sourced before sweeping the whole tree for semantic duplicates | **Whole-tree straggler search is an acceptance criterion for every single-sourcing slice.** Review found a surviving duplicate on three consecutive deliveries, most recently three in merge `ec4d732c4`: fractional CR labels outside `formatCr`, drawing-tool defaults outside `DEFAULT_STROKE_COLOR`/`DEFAULT_STROKE_WIDTH`, and the freehand preview threshold outside `MIN_FREEHAND_POINTS`. Search by both identifier and literal/semantic role; a new canonical export makes an undiscovered live copy more misleading, not less. **The criterion held on both later deliveries** — E1's sweep was clean, and the client cluster's swept `packages/`, `scripts/` and e2e clean, each independently confirmed by three panelists. Keep the check. |
| Add the user-targeted `character:associationChanged` event for the assignment cache affordance without new product evidence | Leaf 63 invalidates the initiating client's entire `character.get` family after assignment or unassignment (`5fd87705c`). This avoids reconstructing old/new identities: all local matches become stale, active sheets refetch immediately, and inactive sheets refetch when next opened. Authoritative cross-client delivery would still require a shared event contract, a global client subscription plus reconnect invalidation, registry fan-out, and affected-id capture across assignment, unassignment, and campaign deletion. The remaining mismatch has **no time bound** — `staleTime` schedules no refetch — and can persist until an applicable trigger such as stale focus/remount, reconnect for an already-linked sheet, or another invalidation. Declining the event is an explicit low-severity product tradeoff, not a bounded-staleness claim. Reopen if real-session impact justifies the machinery; never claim local family invalidation establishes cross-client authority. |
| Give `eslint-config/` its own Vitest project merely to colocate its three config-focused suites | Leaf 38 implemented and then removed this split. The suites already run in the `eslint-rules` project, moving them added no behavioral assertion, and Vitest's glob thresholds key off covered source paths rather than the project containing a test. The split instead added routing, worker, manifest, hook, type/lint, inventory, generated-doc, and second-command maintenance. Keep `eslint-rules/*` changes forcing the complete lint-rule project so the filesystem guards run; revisit project ownership only if a concrete isolation or behavioral-coverage need appears, not because the directory names differ. |
| Rebuild a shared manifest, fixture framework, or arbitrary Vitest/shell-list parser for the two lint-ratchet sandbox copy sets | Leaf 68 closed the observed failure at its source with two focused assertions over the lists each sandbox already consumes. Both reuse `validateSeedImportClosure` and run before fixture construction. The shell loop remains correctly marked `unmodelled-copy` for the generic path-policy analyzer because its list includes a `git ls-files` pipeline; that limitation is not an invitation to teach the analyzer arbitrary dynamic pipelines. Derive a list only if a future concrete need makes local assertion materially insufficient. |
| Add a separate failed-campaign-lookup roll-hook composition test merely to complete leaf 69's optional direction | The rendered positive control is now non-vacuous, both independent roll hooks are already asserted at the sheet composition seam, and `sheet-campaign-context.test.ts` is the authoritative matrix proving that `campaignIdentity` preserves the raw id for `resolving`, `nonmember`, `error`, and `member`. Repeating only the `error` row in the page suite adds mock setup without a distinct contract. Reopen only if the projection or hook wiring changes enough that the existing two layers no longer compose transparently. |

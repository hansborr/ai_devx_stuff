# 27. Server names the CharacterStats concept "character-live-state" while shared/Prisma/client all call it "stats", with no breadcrumb

Status: Done — implemented 2026-06-14 (batch 5a)
Theme: cross-layer naming asymmetry · Area: server · Severity: low · Size: S

Source: codebase maintainability/onboarding audit 2026-06-13 (lens: naming-consistency); evidence independently re-verified. · Confidence: high

## Problem
One domain entity is named two different ways depending on the layer, with nothing connecting the names. The shared contract (`characterStatsSchema` / `type CharacterStats`), the Prisma model (`CharacterStats`), and the client hook (`use-character-stats.ts`, `useCharacterStats`, `trpc.character.updateStats`) all call it "stats" — yet the server keeps the play-time mutation logic in `services/character-live-state/` and re-aliases its exports to `useLiveFeature` / `updateLiveStats` at the router boundary. The strings "live-state" / "LiveState" appear **zero** times anywhere in `packages/shared/src` or `packages/client/src`. A new developer who searches the codebase for "live-state" after seeing it in a server import finds it dead-ends at the server tier, and a developer who starts from the `CharacterStats` schema or the `use-character-stats` hook has no pointer telling them the server-side owner lives under a differently-named directory. The module's own `MODULE.md` names the same thing both ways one line apart ("character-live-state module" then "Concepts: character stats...") without ever mapping the `CharacterStats` contract to the directory, so the only way to learn the equivalence is to read the import graph.

## Evidence
- `packages/server/src/services/character-live-state/MODULE.md:1,3` — heading "character-live-state module" (line 1) but "Concepts: character stats, HP, conditions, spell slots..." (line 3); no line ties the directory name to the `CharacterStats` shared contract / Prisma model.
- `packages/server/src/services/character-live-state/stats-conditions.ts:51` — the module's primary command is `export async function updateStats(...)`; it returns shared `CharacterStats` (imported line 2) and writes the `CharacterStats` Prisma rows via `updateCharacterStatsLocked*` (lines 14-16). The directory name is the only place "live" appears.
- `packages/server/src/routers/character.ts:25,30` — the router re-aliases the service exports to "Live" names that exist nowhere else: `import { useFeature as useLiveFeature }` (25) and `updateStats as updateLiveStats` (30) (also `addCondition as addLiveCondition`, `adjustHp as adjustLiveHp`, `removeCondition as removeLiveCondition`, 27-29). The shared inputs they consume are `UpdateCharacterStatsInput` etc. — "stats", not "live".
- `packages/shared/src/schemas/character.ts:125,155` — `export const characterStatsSchema` (125) and `export type CharacterStats` (155); no "live"/"live-state" anywhere in the contract.
- `packages/server/prisma/schema.prisma:917` — `model CharacterStats { ... }`; the persisted model is "stats".
- `packages/client/src/hooks/character-sheet/use-character-stats.ts:23,94,100` — client hook is uniformly "stats": `updateStats` (23), `export function useCharacterStats` (94), `trpc.character.updateStats.mutationOptions` (100); imports `CharacterStats` from the shared schema (line 2). No awareness of "live-state".
- `rg -ci 'live.?state' packages/shared/src` = **0**; `rg -ci 'live.?state' packages/client/src` = **0** (re-run 2026-06-13). The concept name is server-local with no cross-tier breadcrumb.

## Proposed direction
Fix shape only — do not rename anything yet; the cheapest correct fix is a **breadcrumb, not a rename**.

1. **Add the missing mapping to `MODULE.md`** (lowest-risk, ship first). After the `## Purpose` block in `packages/server/src/services/character-live-state/MODULE.md`, add a one-line "Contract" note: this module is the server-side owner of the shared `CharacterStats` contract (`packages/shared/src/schemas/character.ts` `characterStatsSchema` / `type CharacterStats`) and the `CharacterStats` Prisma model; "live-state" is the server's name for the play-time *mutation* surface of that same entity (vs. character creation/level-up, which own structural writes). This makes the directory name discoverable from the concept name without touching any code.
2. **Add the reverse breadcrumb at the contract** — a short comment next to `characterStatsSchema` in `packages/shared/src/schemas/character.ts` (and/or at the top of the client `use-character-stats.ts`) pointing to `services/character-live-state/` as the server owner of play-time mutations. Honor the package-flow order (shared → server → client): the shared comment is the canonical anchor; server `MODULE.md` and the client hook reference it, not the reverse.
3. **Reconsider the `useLiveFeature` / `updateLiveStats` router aliases** (optional, follow-up). These rename the service's already-clear `useFeature` / `updateStats` to "Live" names that match nothing in the contract. Either drop the aliases (import under the canonical names) or, if a disambiguation is genuinely needed at the router (e.g. against a same-named create/level-up import), prefer a prefix that exists in the domain vocabulary. Confirm there is no naming collision first via `bun run code:intel -- refs` on the call sites before removing an alias.
4. **TDD note:** this is naming/docs, so there is no behavior to pin with a unit test; the regression guard is the existing module test seams in `MODULE.md` ("Test Seams") plus the `MODULE.md` freshness expectation. If step 3 removes a router alias, re-run the existing character router tests (the tRPC input/output + auth-plumbing coverage the module already calls for) to confirm the rename is purely lexical. No new test file is warranted for a comment-only change.

## Scope / caveats
- **In scope as naming-consistency / onboarding discoverability**, not duplication or dead code: there is no duplicated implementation and no unused symbol here — `character-live-state` is the single, live owner of these mutations and every alias is used. This is explicitly **not** a drift-ai near-duplicate/dead-code finding (those are owned by `docs/agent_notes/backlog/drift-ai-findings/`); the cost is purely "two names for one concept with no breadcrumb," which raises a new developer's time-to-understanding.
- Do **not** rename the `character-live-state/` directory or the Prisma `CharacterStats` model as part of this leaf. A directory rename ripples across `MODULE.md`, the lint-coverage-map rows, import paths, and `code:intel` expectations; a Prisma model rename is a migration (`docs/guides/add-prisma-migration.md`). The intentional, low-risk fix here is the breadcrumb (steps 1-2); the alias cleanup (step 3) is a small, optional follow-up.
- Distinct from existing backlog items: not a lint-debt drain, not a useEffect/guardrail item, not a Storybook/component-catalog item, not a dependency bump, and not a UX/infra audit. No existing leaf addresses the live-state-vs-stats naming asymmetry.
- Sequencing: steps 1-2 are independent and can land alone for most of the value; step 3 should follow only after a `code:intel` check confirms no collision motivated the aliases.

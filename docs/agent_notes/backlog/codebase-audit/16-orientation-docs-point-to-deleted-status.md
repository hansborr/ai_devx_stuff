## Problem
Three orientation docs tell a newcomer (or onboarding agent) that current execution status lives in `docs/agent_notes/STATUS.md` and `docs/agent_notes/NEXT.md`. Neither file exists — both were deleted in commit `744b9424` ("docs(agents): remove STATUS.md and NEXT.md") — and the `agent_notes` folder map never lists them; the real surfaces are `LOG.md` plus the roadmap. Worse, the offender is `docs/architecture-plan.md`, the doc AGENTS.md names as a key entry point: its second sentence (lines 3-5) sends the reader to two dead files before any architecture content. A first-time reader who follows the pointer hits a missing file, cannot tell whether the project lost its status tracking or they checked out a broken tree, and burns time reconstructing "where is current status actually written?" — a pure, high-confusion tax at the very front door that a one-commit fix removes.

- `docs/roadmap/developer-experience.md:3` — "Use `docs/agent_notes/NEXT.md` as the active queue; promote one leaf at a time from this file." Points to a deleted file.

- `find docs -iname STATUS.md -o -iname NEXT.md` returns nothing — both files are absent from the worktree.

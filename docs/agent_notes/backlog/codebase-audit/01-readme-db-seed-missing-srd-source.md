Status: Done — 2026-06-13 (branch feat/codebase-audit-01-srd-seed). ## Decision (locked 2026-06-13)
**Take option (b): vendor the SRD reference data into the repo. Do NOT use a git submodule or a fetch-on-clone script.** `db:seed` is on the README first-run path, so it must work from a bare clone with no network and no provisioning ritual.

Rationale (verified at HEAD):
- **Size is a non-issue.** The 15 files the seed actually reads total ~290 KB (the whole `docs/refs/5e-database/src/2024` dir is 392 KB); the repo already commits ~1.5 MB of derived SRD JSON under `packages/server/src/seed/data/`. Vendoring the reference tables is a rounding error against what is already committed.
- **A submodule/fetch script makes onboarding *worse*** — it reintroduces the same ENOENT class (forgotten `git submodule update`) or a first-run network dependency, and a clone pulls the entire upstream repo (all editions) just to read 290 KB. That friction is exactly what this audit exists to remove.
- The committed-vs-checkout asymmetry is historical accident (spells/monsters/magic-items needed `generate-*` transforms, so their output was committed; the reference tables are read raw, so nobody vendored them), not a principle.

**Licensing diligence is mandatory before committing — do not assume.** The upstream `5e-bits/5e-database` README states the code is MIT and *"the underlying material is released using the Open Gaming License Version 1.0a"*, which contradicts Musi's `docs/srd-data-sources.md` (CC-BY-4.0). Resolution: Musi reads only `src/2024/`, which is WotC **SRD 5.2.1** content = **CC-BY-4.0**, so Musi's attribution is the correct one for the content; the upstream's blanket "OGL 1.0a" line reads as 2014/5.1-centric and stale relative to its own `src/2024` dir. The implementing agent MUST: (1) pin the exact upstream revision; (2) confirm the pinned `src/2024` JSON is SRD 5.2.1 content and is not silently mixing OGL 5.1 rows; (3) write a provenance manifest carrying the WotC SRD 5.2.1 CC-BY-4.0 attribution AND crediting `5e-bits/5e-database` (MIT tooling) + the pinned revision.

Implementation outline (for the next agent): vendor the 15 raw `5e-SRD-*.json` files the seed reads under `packages/server/src/seed/data/` (e.g. a `reference/` subdir), repoint `DATA_DIR` at the committed location, keep `docs/refs/` as *optional reseed input for the `generate-*` scripts only*, then make `README.md` and `docs/srd-data-sources.md` agree (the checkout becomes genuinely optional). Keep the leaf's part-1 (actionable `loadJson` error) as defense-in-depth for the reseed path. Files read raw from `DATA_DIR` today: Alignments, Backgrounds, Conditions, Damage-Types, Equipment, Feats, Languages, Magic-Schools, Proficiencies, Skills, Species, Subspecies, Traits, Weapon-Mastery-Properties, Weapon-Properties.

## Problem
The README Quickstart's Step 4 tells a new developer to run `bun run --filter @musi/server db:seed`, but on a fresh clone that command crashes with `ENOENT`. `db:seed` runs `prisma db seed` → `prisma/seed.ts` → `seedSrd()`, whose very first action is to `readFileSync` SRD JSON out of `docs/refs/5e-database/src/2024/`. That directory is gitignored (`.gitignore:58`), is not a git submodule (no `.gitmodules`), and has zero tracked files — nothing in the README, AGENTS.md, devcontainer, or any provisioning script clones the upstream `5e-bits/5e-database` repo into it. The single doc that mentions the checkout (`docs/srd-data-sources.md`) frames it as "optional." So the canonical, documented first-run path hits a hard wall with an error that points at a path the developer has never heard of, and `db:reset` (which re-runs the seed) fails the same way — exactly the kind of unexplained, undiscoverable failure that costs a new developer hours and erodes trust in the setup docs.

## Evidence
- `README.md:31-33` — Quickstart "4. Set up the database" lists `db:migrate` then `db:seed` with **no** SRD-fetch step between clone and seed.
- `packages/server/package.json:19,21` — `"db:seed": "prisma db seed"` and `"db:reset": "prisma migrate reset"` (migrate reset re-invokes the seed, so it breaks identically).
- `packages/server/prisma/seed.ts:22` — `main()` calls `await seedSrd(prisma)`; this is the `prisma db seed` entrypoint.
- `packages/server/src/seed/seed-srd.ts:240-242` — `seedSrd` runs `seedAbilityScoresAndSkills(prisma)` first, which at `:95` calls `loadJson("5e-SRD-Skills.json")` — the first SRD read, so the crash fires before any checked-in seed data is touched.
- `packages/server/src/seed/seed-srd.ts:16-21` — `DATA_DIR = resolve(import.meta.dirname, "../../../../docs/refs/5e-database/src/2024")`; `loadJson` does a bare `readFileSync(resolve(DATA_DIR, filename), "utf-8")` with **no** existence check, fallback, or actionable error. Same `DATA_DIR` + unguarded `loadJson`/`readFileSync` pattern in `seed-srd-reference-tables.ts:10,46-47`, `seed-srd-equipment.ts:11,251`, and `seed-srd-backgrounds.ts:13,122`.
- `.gitignore:58` — `docs/refs/` is ignored. `git ls-files docs/refs/` returns zero tracked files; `.gitmodules` does not exist, so it is not provisioned as a submodule either.
- `docs/srd-data-sources.md:19-22` — describes `docs/refs/5e-database/src/2024/` as an "optional local checkout … Not committed; the seed scripts read from these paths only when an operator has cloned the upstream repos," i.e. the one place this is mentioned both buries it and calls it optional, contradicting the README path that requires it.

## Proposed direction
Fix shape (do not implement here); two complementary parts, smallest-first:

1. **Make the failure self-explanatory (server, fast win).** Wrap `loadJson` in `seed-srd.ts` (and the sibling `DATA_DIR` readers in `seed-srd-reference-tables.ts`, `seed-srd-equipment.ts`, `seed-srd-backgrounds.ts`) so a missing `DATA_DIR`/file throws a single, actionable error naming the absent path and the exact provisioning command, instead of a raw `ENOENT`. TDD: add a focused test beside the seed code (e.g. `packages/server/src/seed/seed-srd.test.ts`) that points `DATA_DIR` (or a small injected base-path) at an empty temp dir and asserts the thrown message names the missing directory and the fetch step — run via `bun run test -- packages/server/src/seed/<file>`.
2. **Provision or document the source (docs + tooling).** Either add an explicit Quickstart step (a `bun run` script that clones/pins the upstream `5e-bits/5e-database` revision into `docs/refs/`, or a documented submodule) **before** `db:seed`, or — if checked-in seed data is the long-term intent (spells/monsters/magic-items already read from the committed `packages/server/src/seed/data/` dir, e.g. `seed-srd-spells.ts:18`) — record that asymmetry in `docs/srd-data-sources.md` and stop calling the checkout "optional" while the README hard-requires it. Update `README.md:31-33` and `docs/srd-data-sources.md:19-22` to agree, and pin the upstream revision as that doc already asks reseeders to do (`:33-35`). Keep the package-flow note in mind: this is server/docs only — no shared schema or client change.

## Scope / caveats
- This is an **onboarding-setup / first-run correctness** finding (the documented Quickstart path crashes), not a duplication or dead-code finding — the `DATA_DIR` readers are live, required code on the seed path, so it is explicitly **not** owned by `docs/agent_notes/backlog/drift-ai-findings/`. It is distinct from the agent-harness ergonomics work in `agent-friction-2026-06/` (this is a human fresh-clone wall, not agent test/lint ergonomics) and from the production/UX audits.
- Do **not** commit the upstream SRD JSON wholesale as a "fix" without a licensing/size decision — `docs/srd-data-sources.md:6-14` records the CC-BY-4.0 attribution requirement, and the existing design deliberately keeps `docs/refs/` out of git. The clean resolutions are: (a) a pinned, scripted/submodule checkout, or (b) commit only the derived seed JSON under `packages/server/src/seed/data/` (the pattern already used for spells/monsters/magic-items) and update the docs to match. Choosing between them is part of this leaf; do not silently flip the gitignore.
- Touch only the seed-path error handling, the README Quickstart, and `docs/srd-data-sources.md`. Leave the already-committed `seed/data/*.json` readers and the `generate-*` scripts alone.

# 34. resolveSavingThrow tests live in combat.test.ts, breaking the colocated rules-test convention (no saving-throw.test.ts)

## Problem
`packages/shared/src/rules/` follows a strict one-rule-one-sibling-test convention: every logic rule file has a colocated `<name>.test.ts` (`attack-roll.ts`/`attack-roll.test.ts`, `attack-damage.ts`/`attack-damage.test.ts`, `concentration-save.ts`/`concentration-save.test.ts`, `d20-roll.ts`/`d20-roll.test.ts`, etc.). `saving-throw.ts` is the lone exception — it has **no** `saving-throw.test.ts`. Its entire test suite instead lives inside `combat.test.ts`, a file whose source (`combat.ts`) exports only encounter state-machine, action-economy, and HP-adjustment logic and nothing about saving throws. A new developer asked to change `resolveSavingThrow` — which carries subtle, easy-to-break 5.5e semantics (no auto-success/fail on nat 20 / nat 1 for saves, half-damage-on-save flooring) — will look for `saving-throw.test.ts` by the convention every other rule taught them, find nothing, and reasonably (and wrongly) conclude the function is untested, risking a change that ships without re-running its real coverage.

## Evidence
- `packages/shared/src/rules/` — directory listing confirms every logic rule `.ts` has a sibling `.test.ts` **except** `saving-throw.ts` (the only other test-less `.ts` is the pure data file `damage-types.ts`). Verified: `saving-throw.test.ts` does not exist (`ls` → "No such file or directory").
- `packages/shared/src/rules/saving-throw.ts:37` — exports `resolveSavingThrow`; doc comment at lines 30-36 spells out the subtle 5.5e rules ("No auto-success/fail on nat 20/1 (strict 5.5e for saves)", half-damage flooring at line 66 via `Math.floor(fullDamage / HALF_DIVISOR)`).
- `packages/shared/src/rules/combat.test.ts:11-12` — cross-imports `SavingThrowInput` and `resolveSavingThrow` from `./saving-throw.js` (not from the file under test's own source).
- `packages/shared/src/rules/combat.test.ts:360-575` — the entire `describe("resolveSavingThrow")` block (16 `it()` cases across fail/succeed/tie, half-damage, description formatting, and advantage/disadvantage) lives here, far from its source.
- `packages/shared/src/rules/combat.ts:15-80` — `combat.ts` exports only `isValidTransition`/`getValidTransitions`, `ACTION_ECONOMY_TYPES`/`FRESH_ACTION_ECONOMY`/`hasActionsRemaining`, and `HpAdjustment*`/`applyHpAdjustment`. Nothing saving-throw related, so the host test file's source is unrelated to the block it carries.
- `packages/server/src/services/spell-casting/resolve-spell.ts` — the lone server consumer of `resolveSavingThrow`, underscoring that this is live rules logic a newcomer will need to trust the tests for.

## Proposed direction
Fix the colocation only; do not touch `resolveSavingThrow`'s behavior or its assertions. Shape: create `packages/shared/src/rules/saving-throw.test.ts` and **move** the `describe("resolveSavingThrow")` block (and only that block) out of `combat.test.ts:360-575` into it, carrying the `SavingThrowInput`/`resolveSavingThrow` imports down from `combat.test.ts:11-12` (drop them from `combat.test.ts` once they are unused there) and the `// resolveSavingThrow` section banner. The remaining `combat.test.ts` then covers exactly what `combat.ts` exports, restoring the one-to-one convention. This is a pure test-file move within `packages/shared`, so the package-flow order (shared → server → client) is not engaged. Verify by running both files: `bun run test -- packages/shared/src/rules/saving-throw.test.ts` and `bun run test -- packages/shared/src/rules/combat.test.ts` (same 16 `it()` cases, same pass count, zero assertion edits). No new test logic is added — this is a relocation, not new coverage.

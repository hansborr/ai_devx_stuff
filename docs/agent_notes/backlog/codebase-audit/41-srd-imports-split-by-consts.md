# 41. srd.ts splits its import section with five module-level const declarations mid-file

Status: Done — 2026-06-13. Hoisted the two trailing import blocks (`srd-narrowing`, `srd-query-helpers`) into the contiguous import section and moved the five derived-schema consts to sit immediately after the now-complete imports. Pure positional reorder, no behavior change; `bunx eslint packages/server/src/routers/srd.ts` exit 0 (simple-import-sort satisfied, no re-sort needed), `bun run typecheck` clean, `srd.test.ts` 20 tests green.
Theme: import-section hygiene · Area: server · Severity: low · Size: XS

Source: codebase maintainability/onboarding audit 2026-06-13 (lens: complexity-hotspots); evidence independently re-verified. · Confidence: high

## Problem
`packages/server/src/routers/srd.ts` opens with imports (lines 1-39), then inserts five module-level `const` schema-derivation statements (lines 41-45), then resumes a second block of imports (lines 46-55) before any other code. A contiguous top-to-bottom import section is a baseline expectation a new developer relies on when scanning a file's dependencies; here the second import block is buried below executable code, so a reader skimming the head of this 550-line router can easily conclude the imports end at line 45 and miss that `srd-narrowing` and `srd-query-helpers` are pulled in. The five derived-schema consts are also physically separated from the schema imports they consume (e.g. `abilityAbbreviationSchema` is imported on line 3 but `abilityAbbreviationsSchema = z.array(abilityAbbreviationSchema)` lives 39 lines later, sandwiched between import blocks), making the data-flow harder to follow than if the consts sat together after a complete import section.

## Evidence
- `packages/server/src/routers/srd.ts:1-39` — first import block (shared spell/SRD schemas, `zod`, `Prisma` type, trpc, prisma-json, spell-mapping).
- `packages/server/src/routers/srd.ts:41-45` — five executable `const` declarations inserted mid-head: `stringArraySchema`, `abilityAbbreviationsSchema`, `equipmentOptionsNullableSchema`, `weaponDataNullableSchema`, `armorDataNullableSchema`.
- `packages/server/src/routers/srd.ts:46-55` — second import block resumes *after* the consts: `../utils/srd-narrowing.js` (46-50) and `../utils/srd-query-helpers.js` (51-55).
- `eslint.config.js` + `eslint-config/code-quality-configs.js:130-131` — the only import-related lint is `simple-import-sort/imports`/`exports`; it sorts each *contiguous* import run but does not require imports to precede other statements, so it does not flag this split. No `import/first` (or `import-x/first`) rule is configured anywhere under `eslint-config/`.
- Repo-wide check (awk over `packages/server/src/routers/*.ts`): `srd.ts` is the **only** router where a top-level `import` appears after the first top-level code line — first code at 41, a later import at 51.

## Proposed direction
Pure mechanical hoist, no behavior change: move the two trailing import blocks (lines 46-55) up to join the first import section (after line 39), then place the five derived-schema consts (currently 41-45) immediately below the now-complete import section, just above the `// Prisma include / select shapes` comment banner (line 56). `simple-import-sort/imports` will re-sort the merged import run on the next lint; verify ordering with `bun run lint -- packages/server/src/routers/srd.ts`. There is no behavior to TDD here — the existing `srd` router tests (`bun run test -- packages/server/src/routers/srd.test.ts` if present, else the e2e/integration coverage that already exercises these procedures) must stay green to confirm the reorder is purely positional. Optionally, in a separate follow-up, evaluate adding an `import/first`-style rule so this split cannot silently recur across routers — but that is a lint-policy decision and should NOT be bundled into this XS hoist (and lint-policy/ratchet governance is owned elsewhere; see Scope).

## Scope / caveats
Touch only `packages/server/src/routers/srd.ts`; do not move the consts into a shared module or change what they derive — this is a within-file ordering cleanup, not a refactor of the schema-derivation logic. This is explicitly NOT a duplication or dead-code finding (those are owned by `docs/agent_notes/backlog/drift-ai-findings/`): all five consts are live and uniquely defined, and no imports are removed or merged for dedup reasons — the imports are only relocated. Adding a new `import/first` lint rule (and any ratchet wiring it would need) is deliberately left out of scope because lint-debt drains and ratchet governance are owned by `docs/agent_notes/finished_work/lint-followups-2026-06.md` and the lint-ratchet leaves; this leaf is the one-file hoist only. Low risk: no runtime semantics depend on the relative position of imports vs. these `const` initializers (the consts reference only already-imported bindings, and ES module imports are hoisted regardless of source position), so the reorder is behavior-preserving.

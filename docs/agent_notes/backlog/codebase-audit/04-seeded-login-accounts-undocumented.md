# 4. Seeded dev login accounts (dm@example.com / player1 / player2, password `password123`) are absent from the onboarding path

Status: Done — 2026-06-20. Added a "Log in with a seeded account" step (step 6) to the `README.md` Quickstart with a 3-row table (email · display name · role) mirroring `seed-users.ts`, the shared `password123` flagged as dev-seed-only, and a pointer to re-run `db:seed`/`db:reset`. Doc-only; no seed/code change, no new test.
Theme: onboarding dead-end · Area: docs · Severity: low · Size: XS

Source: codebase maintainability/onboarding audit 2026-06-13 (lens: onboarding-setup); evidence independently re-verified. · Confidence: high

## Problem
`bun run --filter @musi/server db:seed` creates three login-able users — `dm@example.com`, `player1@example.com`, `player2@example.com`, all with password `password123` — but the developer-facing onboarding path never names them. A new developer who follows the README Quickstart top-to-bottom (`bun install` → `db:migrate` → `db:seed` → `bun run dev`) arrives at the login screen at `http://localhost:8000` with no documented credentials and must either grep the seed source or register a fresh account before they can see anything. The only place the accounts are written down is a buried agent-notes audit artifact (`docs/agent_notes/backlog/ux_ui_audit/README.md`) that a first-time developer has no reason to open — so in practice the credentials are discoverable only by reading server source. This is pure time-to-first-success friction: the very last step of "get the app running" is undocumented.

## Evidence
- `packages/server/src/seed/seed-users.ts:6-12` — `SEED_PASSWORD = "password123"`; `SEED_USERS` = `dm@example.com` (Dungeon Master), `player1@example.com` (Aragorn), `player2@example.com` (Gandalf). `seedUsers` upserts all three with that bcrypt-hashed password (`seed-users.ts:14-22`), so they are real, login-able accounts.
- `packages/server/prisma/seed.ts:21` — the `db:seed` entrypoint runs `await seedUsers(prisma)` (before `seedSrd`), so these three users are created on every seed.
- `README.md:17-41` — the Quickstart ends at `bun run dev` and "The client runs at http://localhost:8000"; it never mentions logging in or which account to use.
- `README.md:62-69` — the Database table documents `db:migrate` / `db:seed` ("Seed development data") / `db:studio` / `db:reset` but lists no seeded login account.
- `AGENTS.md:16` — `db:seed` is mentioned only as one of the `db:{push,seed,reset,studio}` "local DB utilities; package filter required" — no credentials.
- `docs/agent_notes/backlog/ux_ui_audit/README.md:18-24` — the *only* doc that records the accounts: a "Seeded accounts (password `password123`)" table inside a dated UX-audit backlog folder, not part of the onboarding path. (Same creds also appear ad hoc at `docs/agent_notes/backlog/ux_ui_audit/findings/dm-perspective.md:5` and `.../VERIFICATION.md:5`.) None of these is reachable from the README/AGENTS onboarding flow.

## Proposed direction
Documentation-only; no code change. Add a short "Now log in" step as the natural Quickstart tail in `README.md` (after step 5 "Start development servers"), listing the three seeded accounts and the shared `password123` — sourced from `seed-users.ts` so the doc and seed stay consistent. Optionally add a one-line cross-reference in the Database section (`README.md:62-69`) noting that `db:seed` creates these login accounts. Keep it terse (a 3-row table mirroring `seed-users.ts:8-12`: email · display name · role) and call out that the password is dev-seed-only, never a real credential. This pairs naturally as the final "now log in" step of the `db:seed`/SRD onboarding fix if that leaf lands first. No new test is warranted for a docs addition; the only guard worth considering is a tiny assertion (in an existing seed test, if one exists under `packages/server/src/seed/`) that `SEED_USERS` emails/password match what the README documents, but that is optional and out of proportion for an XS docs change — do not add a new test file for it.

## Scope / caveats
Touch only the developer-facing onboarding docs (`README.md`, optionally an `AGENTS.md` pointer). Do NOT edit `seed-users.ts`, the seed pipeline, or change the password — the goal is to surface existing behavior, not alter it. Do NOT rewrite or relocate the `docs/agent_notes/backlog/ux_ui_audit/` artifacts; those are dated audit records and are out of scope here. This is not a duplication/dead-code finding (those are owned by `drift-ai-findings/`): the accounts are live and used; the gap is purely discoverability. It is distinct from the `ux_ui_audit` backlog (a UX/product audit that merely *uses* these creds for Playwright walkthroughs and does not propose documenting them in the onboarding path) and from any infra/production-readiness item, since this is local dev-onboarding docs only. Sequencing: low-risk and independent; can land alone or fold into the `db:seed` onboarding-step fix.

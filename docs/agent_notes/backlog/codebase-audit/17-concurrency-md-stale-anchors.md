## Problem
`docs/CONCURRENCY.md` is the authoritative concurrency rulebook — `AGENTS.md` lists it under Key docs, the dedicated guide `docs/guides/add-race-sensitive-mutation.md` walks an author through it section by section, and a dozen-plus source files, migrations, and a `*-MODULE.md` cite it by name (e.g. `packages/server/src/utils/prisma-types.ts`, `services/rest-service.ts`, `routers/invite.ts`). Two of its named anchors have drifted, so a newcomer following the rulebook to find the actual protection mechanism lands on nothing. (1) It says any field not in `NON_RACING_FIELDS` (defined in `encounter.ts`) requires `expectedVersion` — that constant has never existed; the real guard is the *inverted* `PARTICIPANT_FIELD_KIND` exhaustive-classification map (a stronger fail-closed guarantee than the doc's opt-out wording, since every new schema field must be classified or the build breaks). (2) It says the `advanceTurn` conditions read-modify-write (the C2 fix) lives in `turn-service.ts`, a file that does not exist anywhere in the repo; the logic is in `services/combat-actions/turn-transaction.ts`. Both drifts misdescribe the mechanism, not just the path, so the doc actively misleads about how the invariant is enforced.

## Evidence
- `docs/CONCURRENCY.md:323-326` — "Any field NOT in `NON_RACING_FIELDS` (defined in `encounter.ts`) requires `expectedVersion`… Future schema additions default to CAS-protected unless explicitly added to the whitelist." Describes an opt-out allowlist.
- `rg -n "NON_RACING_FIELDS" packages/server/src/` — 0 matches; the named constant does not exist in server source.
- `packages/server/src/routers/encounter.ts:77-94` — the real construct is `const PARTICIPANT_FIELD_KIND = { … } as const satisfies Record<keyof UpdateParticipantInput, "racing" | "non-racing">` — an exhaustive map that classifies *every* field (not an allowlist of exemptions). The header comment (lines 72-76) states classification is "fail-closed by construction: adding a field to the schema without an entry below is a build error," i.e. new fields default to *requiring* classification, the opposite of the doc's "default to CAS-protected … unless added to the whitelist" framing.
- `packages/server/src/routers/encounter.ts:96-109` — `assertVersionForRacingFields` is what enforces the `BAD_REQUEST`, by iterating `PARTICIPANT_FIELD_KIND` for `"racing"` entries — confirming the mechanism the doc attributes to a non-existent allowlist.
- `docs/CONCURRENCY.md:92` — "`conditions` is read-modify-write in `turn-service.ts` (the C2 fix)".
- `rg -rn "turn-service" packages/ docs/ scripts/` — no `turn-service.ts` file exists anywhere; the only references are the `docs/CONCURRENCY.md:92` line itself and a corroborating comment at `packages/server/src/routers/encounter-combat-concurrency.test.ts:529` (`// turn-service path (now combat-actions/turn-transaction.ts):`), which already names the correct relocated file. (The stale anchor is the doc; the test comment is right.)
- `packages/server/src/services/combat-actions/turn-transaction.ts:1,7,56-67` — the actual home of the conditions RMW C2 fix: `updateParticipantStatsLocked(tx, nextParticipant.id, (fresh) => { … tickConditions(rawConditions) … return { …, conditions: tickedConditions } })`, with the module header (lines 11-20) documenting exactly the "read next participant inside the tx, version-CAS tick, lost-update race if done pre-tx" rationale the doc's C2 entry references.

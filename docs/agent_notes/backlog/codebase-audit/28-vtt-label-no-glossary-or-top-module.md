## Problem
"VTT" is a top-level organising concept in the client — `components/vtt/`, `hooks/vtt-drawer/`, `stores/vtt-drawer-store.ts`, the `VttSurface` component (~44 files mention the token) — yet the abbreviation appears **0 times anywhere under `packages/server/src`** and is never defined in any glossary (there is no glossary doc at all under `docs/`). The same tabletop UI is physically split across four sibling directories (`components/vtt/`, `campaign/combat/`, `campaign/maps/`, `campaign/tokens/`) backed by three differently-prefixed stores (`combat-store`, `map-canvas-store`, `vtt-drawer-store`), and `VttSurface` is mounted by **both** `combat-map-content` and `map-detail-content` with no name or doc anchor tying those two screens together. A new developer who greps the server for "VTT" to find where this feature persists gets nothing, and has no single line telling them VTT === the `Encounter` / `Map` / `Token` data model — so the client label and the server contract read like two unrelated features. This is a glossary/anchor gap that costs time-to-understanding and discoverability, **not** an undocumented-ownership gap: "Virtual Tabletop" *is* expanded in AGENTS/README/schema, and per-directory ownership *is* documented in sibling MODULE.md files.

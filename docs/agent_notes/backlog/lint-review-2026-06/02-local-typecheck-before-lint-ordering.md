# Local Typecheck-Before-Lint Ordering

Status: Done (2026-06-12, landed in "fix(lint): explain missing dist before
lint" and "test(lint): cover dist preflight wrappers")
Order: 02
Source: Codex review item 1.

## Context

CI typechecks before lint, with an explicit comment that `tsc -b` builds
referenced-project dists that type-aware ESLint depends on
(`.github/workflows/ci.yml:68`). Locally, the generated verify step order runs
`lint` before `typecheck` for every consumer (`verify`, `verify_changed`,
`verify_parallel`, `pre_commit` — see `scripts/verify/steps.generated.sh:12`),
and the parallel consumer runs them concurrently.

On a fresh checkout (or after deleting dists), local lint can therefore fail
with confusing project-service parser errors that CI never produces, and the
fix ("run typecheck first") is not stated anywhere in the failure output.

`scripts/verify/steps.generated.sh` is generated by
`scripts/harness/generate-verify-steps.ts` from the harness controls manifest;
do not hand-edit it.

## Scope

Pick one (or layer both):

- Reorder the generated step arrays so typecheck precedes lint for serial
  consumers, and express the dependency (or a cheap dist-existence pre-step)
  for the parallel consumer. This touches the controls manifest and generator,
  so coordinate with the watchlist's harness-controls execution-model entry
  if that lands first.
- Add a fast preflight to `scripts/lint.sh` (and `lint-changed.sh`) that
  detects missing referenced-project output and fails with an actionable
  "run `bun run typecheck` first" diagnostic instead of raw parser errors.

Either way, document the dependency in the harness/verify docs so reference
adopters see it.

## Definition Of Done

A fresh checkout running `bun run verify` (or any verify consumer) either
orders typecheck before lint or fails the lint step with a diagnostic that
names the missing prerequisite — never with bare project-service errors.

## Verification

- Fresh-checkout (or `rm -rf packages/*/dist`) run of `bun run verify` and
  `bun run verify:parallel`
- Generator drift check for `steps.generated.sh` if step order changes
- `bun run verify:changed`

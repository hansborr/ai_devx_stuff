# 13 — lint-coverage-map.md is hand-edited under docs/generated/

Status: Done — satisfied by harness-audit leaf 61 (`8bde98a0`)
Track: T (tooling) · Priority: P3 · Size: S

## Evidence (verified 2026-07-11; re-verified in 2026-07-11 adversarial triage; re-verify before implementing)

- `docs/generated/lint-coverage-map.md` (~line 13) — self-describes as
  "hand-derived from `git ls-files`"; `package.json:104-106` offers only
  `docs:lint-coverage-map:{check,audit,suggest}`, no generator.
- `scripts/lint-coverage-map-check.ts:4,41` — the checker imports
  `configSurfaceEntries` via `eslint-config/config-surfaces.js` (a validating
  loader over `eslint-config/config-surface-manifest.json`), so mechanical
  membership data is machine-readable. But the map's judgment columns are
  not: `scripts/lint-coverage-map-check-suggest.ts:70-112` derives only
  normal-lint/ratchet/status for unaccounted files and emits `none` / `—` /
  `<excluded|not-code|proposed>` placeholders for the `Proposed rule/tool`
  and `Blocker/follow-up` rationale columns. Full generation would just move
  the hand-editing into prose-in-JSON.
- The file is already drift-guarded harder than most generated docs:
  `scripts/verify/steps.generated.sh:45,81,121,157` wires the staged check
  into pre-commit/changed verify and the eslint-reach audit into full verify;
  the checker fails on any tracked in-scope file matching no row.
- `docs/generated/observed_flaky_tests.md` is a second hand-edited file in
  the directory — deliberately so: `scripts/ai-hooks/policy.sh:29` instructs
  agents to append to it. Meanwhile `harness-controls.md` and
  `local-lint-rules.md` carry "Generated by … Do not edit by hand" headers.
  The directory has mixed, undocumented semantics.

The trap is legibility, not staleness: for an adopter copying this harness,
`docs/generated/` promises regenerability that two of its four files don't
have. (Content drift itself is already gated.)

## Do

Do NOT build a generator: the rationale columns are human judgment, a
data-file inversion relocates rather than removes the hand-maintenance, and
the checker's parser would need a matching renderer — churn with no drift
reduction over the existing gate. Instead, make the directory honest:

- Preferred: move `lint-coverage-map.md` to `docs/lint-coverage-map.md`
  (about 15 files reference the path: checker io/tests, `path-policy`,
  `harness.controls.json`, guides, `ai-harness.md`) and move or similarly
  relocate `observed_flaky_tests.md` (3 references, all in
  `scripts/ai-hooks/`); state "hand-maintained, drift-gated by
  `docs:lint-coverage-map:check`" in the map's header.
- Or cheaper: add a `docs/generated/README.md` defining the directory as
  "harness-managed docs" with a per-file ledger of generated vs.
  hand-edited-under-drift-guard.

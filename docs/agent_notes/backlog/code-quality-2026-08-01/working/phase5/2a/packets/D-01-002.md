## Settled direction (implement this; do not re-open it)

Inventory mappers whose actual output schemas use dateTimeField, convert their result contracts to schema input types, and let output parsing normalize Prisma Dates. Deliver domain-bounded slices, using leaf 014's MapLayer convention as the precedent.

## Problem statement from the promotion candidate

dateTimeField is already the shared Date-to-wire-string boundary, but server mappers alternate between schema-input result types that return Prisma Dates and z.infer output types that force each mapper to call toISOString() itself. The duplicate map-layer paths demonstrate both conventions against one schema. This spreads serialization policy across mapper families and permits equivalent paths to drift.

## Verified evidence (existence-checked at step 1b)

- `packages/shared/src/constants.ts:109-111` — dateTimeField already accepts either a string or Date and performs the canonical Date.toISOString() normalization.
- `packages/shared/src/schemas/map.ts:112-113` — Both map-layer timestamps use the shared normalizing field.
- `packages/server/src/utils/map-types.ts:81` — The detail-path mapper contract is derived as z.input<typeof mapLayerSchema>, allowing Prisma Dates to reach the output parser.

## Settled direction (implement this; do not re-open it)

Delete `validateAuthConfig` and its `buildServer` call. Keep `loadServerEnv`'s eager schema parse as the sole startup validation boundary and retain `getJwtSecret` for real consumers.

## Problem statement from the promotion candidate

The named startup validator performs no validation beyond reading an already-parsed value. It creates a false ownership boundary for auth configuration checks.

- `packages/server/src/app.ts:188-195` — buildServer invokes validateAuthConfig as though it were an explicit startup check.

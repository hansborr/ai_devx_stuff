# 102. The generated-docs ownership table labels the hybrid lint coverage map wholly hand-maintained and invites edits to generator-owned bytes

Status: Landed on fix/cq-170
Theme: doc ownership contracts · Area: docs · Severity: low · Size: S

Source: codebase quality audit 2026-08-01 · Confidence: high

## Problem

`docs/generated/README.md` exists for exactly one purpose: it tells a
contributor, before they touch anything in the directory, which files a
generator owns and which they may edit by hand. For
`lint-coverage-map.md` it gives the wrong answer. The row says
"Hand-maintained / Edit the map directly", but the map has hybrid
ownership: its marker-delimited `scripts/drift-ai/*.ts` coverage table is
rewritten by a generator that "preserves every byte outside its one marked
span", and the map explicitly forbids hand-editing inside that span. A
contributor who trusts the directory contract — its stated job — can
hand-edit generated bytes that the next `docs:lint-coverage-map:generate`
run silently clobbers, or that `docs:lint-coverage-map:generate:check`
flags as stale for reasons the README told them could not apply. The harm
is bounded because the map's own header corrects the reader before they
reach the generated span, but an ownership table that lies about
generator-owned bytes is exactly the failure this directory's contract
exists to prevent.

## Evidence

- `docs/generated/README.md:11` — the row: "`lint-coverage-map.md` |
  Hand-maintained | Edit the map directly. …" (it lists only the `:check`
  and `:audit` gates, no generation workflow).
- `docs/generated/README.md:3-5` — the table's charter: "not every file is
  machine-generated. Check the ownership contract below before editing or
  regenerating a file."
- `docs/generated/README.md:14-15` — the closing prose recognizes only two
  categories, "generated" and "hand-maintained"; the map fits neither.
- `docs/generated/lint-coverage-map.md:13-17` — "Source of truth: this
  file has hybrid ownership. The marker-delimited `scripts/drift-ai/*.ts`
  table is generated … The generator preserves every byte outside its one
  marked span."
- `docs/generated/lint-coverage-map.md:95-100` — "**Generated boundary:**
  do not hand-edit text between the drift-ai markers", with
  `bun run docs:lint-coverage-map:generate` as the refresh command and
  `:generate:check` as the freshness check.
- `docs/generated/lint-coverage-map.md:228-232` — the actual generated
  span: `<!-- BEGIN generated: lint-coverage-map drift-ai -->` /
  `<!-- END generated: lint-coverage-map drift-ai -->` markers around the
  344-file drift-ai coverage row.
- `scripts/lint-coverage-map-gen.ts:14-30` — the generator resolves
  `docs/generated/lint-coverage-map.md` as its `outputPath` and splices
  the derived block via `spliceDriftAiCoverageBlock`.
- Both cited scripts exist in root `package.json`:
  `docs:lint-coverage-map:generate` and
  `docs:lint-coverage-map:generate:check` (alongside the `:check`,
  `:audit`, and `:suggest` siblings the README already names).

## Proposed direction

Change `lint-coverage-map.md`'s row in `docs/generated/README.md` from
Hand-maintained to Hybrid, stating that the marker-delimited table is
generator-owned (refresh via its generator) while surrounding policy
prose is edited directly.

Concretely: in the row at `docs/generated/README.md:11`, set the
Ownership cell to `Hybrid` and rewrite the Maintenance-contract cell to
say the drift-ai marker span is owned by
`bun run docs:lint-coverage-map:generate` (freshness:
`docs:lint-coverage-map:generate:check`) and everything outside the
markers is edited directly — keeping the existing `:check` / `:audit`
gate sentences. Mirror the wording already established at
`docs/generated/lint-coverage-map.md:13-17` rather than inventing new
terms, and adjust the two-category closing prose at `README.md:14-15` so
it accounts for the hybrid case.

- The `observed_flaky_tests.md` row and the two fully generated rows are
  accurate; do not restructure the table beyond what the hybrid row and
  the closing prose need.
